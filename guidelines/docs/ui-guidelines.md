# 产品视觉与交互规范

本文件是页面设计、前端实现与代码生成的强制文字依据。设计系统交付包的单一来源为：

- 文字规则与验收：`docs/ui-guidelines.md`
- 机器可读 Token：`tokens/design-tokens.json`
- 组件契约：`components/component-specs.json`
- Ant Design 映射示例：`adapters/ant-design-theme.ts`

原型工程中的 `src/styles/*` 与 `src/app/theme.ts` 仅用于验证规范映射，不属于前端接入源。

静态视觉约束的来源优先级为：页面特殊规则 < 业务组件规则 < 基础组件规则 < Design Token。运行时交互规则不得沿用这条简单覆盖链，必须按第 27.0 节的适用性、冲突与优先级契约求值。页面不得重复定义已存在的 Token。

## 1. Design Token

### 命名

- `--ds-*`：跨产品共享的设计 Token。
- `--app-*`：Web 应用语义变量，兼容既有页面。
- `--robot-*`：机器人工作区语义变量，兼容既有页面。
- 颜色必须使用语义名称，不按视觉值命名；例如使用 `danger`，不得使用 `red`。

### 颜色

- 页面、布局、卡片、弱背景分别使用 `page / layout / surface / soft`。
- 文本按 `heading / text / muted` 三级使用。
- 品牌和状态色按 `accent / info / success / warning / danger` 使用。
- 禁止在组件和业务页面内新增十六进制颜色。3D 场景、坐标轴与图表数据系列也必须引用 `components.scene3d`、`components.chart` 或项目登记的数据可视化 Token；只有 Token 源文件允许保存原始色值。
- 明暗模式必须来自 `THEME_PALETTES`，不得在页面组件中独立维护两套颜色。

### 字体

- 仅使用 `--ds-font-size-*`、`--ds-font-weight-*`、`--ds-line-height-*`。
- 字号只使用偶数阶梯：10 / 12 / 14 / 16 / 18 / 20 / 24px，禁止新增 11 / 13 / 15px 等单数字号。
- 正文默认 14px；辅助信息与紧凑标签 12px；模块标题 16–18px；页面标题 20–24px。
- 正文常规字重 400；交互和标签 500/600；页面标题不超过 700。
- 数字、版本号、坐标、代码和文件名可使用等宽字体 Token。

| 应用位置 | 字号 | 字重 | 行高 | 使用说明 |
| --- | ---: | ---: | --- | --- |
| 页面标题 | 20 / 24px | 600 | tight | Page Header 中的唯一页面标题。 |
| 弹窗标题 | 18px | 600 | normal | Modal Header 标题。 |
| 模块标题 | 16px | 600 | normal | 内容区模块标题。 |
| 正文 / 表单字段 | 14px | 400 | normal | 正文、Input 内容与字段说明主体。 |
| 菜单 / 按钮 | 14px | 500 / 600 | normal | Menu 条目 500；Button 文案 600。 |
| 表头 / 标签 / 辅助信息 | 12px | 500 / 400 | normal | 表头与标签 500；帮助、日期与状态补充 400。 |
| 紧凑补充 | 10px | 400 | normal | 仅限低优先级版本、单位或补充信息。 |

### 间距

- 使用 4px 基础栅格：4、8、12、16、20、24、32、40、48、64。
- 控件内部优先 8/12/16；模块之间优先 16/24；页面区块之间优先 24/32。
- 禁止为“看起来差不多”新增 13px、15px、17px 等临时间距。

### 圆角、阴影、层级与透明度

- 按钮 8px、输入类控件 10px、内部容器 12px、卡片/浮层 16px、胶囊 999px。
- 阴影只使用 `none / xs / sm / card / overlay / dialog` 六级。
- 层级只使用 `base / sticky / dropdown / drawer / modal / toast / tooltip`。
- Disabled 透明度统一为 0.45；不得仅依赖透明度表达 Error 或选中状态。

## 2. 页面布局

- 页面必须使用 `--ds-layout-*`；默认页面边距 24px、模块间距 16px。
- 导航、侧栏、内容区必须是 `flex/grid` 布局，禁止用绝对定位搭建主体结构。
- 主内容必须设置 `min-width: 0`、`min-height: 0`，需要滚动的最近容器负责 `overflow`。
- 固定表格列、吸顶栏、侧栏不得制造无意义竖线；通过背景和阴影表达层级。
- 12 列栅格用于桌面端，移动端降为 4 列。

## 3. 基础组件

- 所有基础控件必须遵循平台发布的 Token、尺寸、状态和无障碍规范；研发可使用团队批准的组件库实现，不得为已有控件另起一套视觉语言。
- 文件选择必须保留浏览器可访问的文件选择行为；不得制作不可访问的伪上传控件。
- 业务页面不得覆盖 Button、Tag、Input、Select、Checkbox、Modal 的字体、尺寸、圆角、描边、禁用或焦点状态。
- 新基础组件必须按适用范围包含 Default、Hover、Pressed、Focus、Selected、Disabled、Loading、Error 状态；`Pressed` 与 `Selected` 不得混用。
- 主操作数量与操作区边界统一见 §13.1.1；危险操作必须使用 danger 状态并二次确认。
- 输入框与选择器必须有可见 Label；Placeholder 不能替代 Label。
- 表格默认表头 44px、数据行 60px；宽表使用内部横向滚动。
- 页面工具栏的搜索框、筛选 Select 与“导入、导出、刷新、新建/新增”操作统一 40px 高；只有整行工具栏明确进入紧凑模式时，次要筛选控件才可统一降为 32px，同一行不得混用 32px 与 40px。弹窗表单输入和 Footer 按钮使用 40px；表格行内操作、标签增删等紧凑控件保持 24–32px。
- 常规文字按钮默认 40px 高，紧凑按钮只允许 32px，迷你图标操作只允许 24px；按钮圆角全部使用 8px，不允许页面自行定义高度或圆角。
- Modal 用于需要确认的短任务；Drawer 用于不离开当前上下文的详情查看与连续配置。两者必须使用产品层已发布组件，不得在业务页面自行搭建浮层外观。
- Dropdown 浮层使用 16px 外圆角、12px 条目圆角、overlay 阴影、危险项独立状态。

### 3.1 组件使用与视觉契约

| 组件 | 视觉与交互规则 |
| --- | --- | --- |
| Button / IconButton | `primary` 只用于当前区域主操作；`secondary`、`text` 不描边；`outline` 仅用于需要弱边界的工具栏操作。高度只允许 24 / 32 / 40px。 |
| Tag / Badge | 仅用于状态、范围、版本、计数等元信息；统一使用语义色填充，**禁止描边和 outline 变体**；不得充当普通按钮。 |
| Input / TextArea | 必须有可见 Label；页面搜索可使用弱填充底，表单控件使用 surface 底与中性描边。 |
| Select / Checkbox | 必须支持键盘操作、可见 Focus 和明确的选中/禁用状态；不得重新制作与平台规范冲突的通用控件。 |
| Modal | 必须包含遮罩、焦点管理以及 Esc/遮罩关闭机制（见 §16.0）；业务层只传入内容和状态。 |

标签与按钮的用途不同：标签不带描边、不承担操作；按钮必须有明确的动作语义。任何页面发现同一语义的标签有的有描边、有的没有，视为规范不通过。

**Closable Tag 变体**：Tag Hover 时右侧出现 `×` IconButton（16px，热区至少 24×24px）；点击 `×` 仅触发移除逻辑，不触发 Tag 本体的点击事件；移除无需二次确认；键盘 Tab 可聚焦到 `×` 按钮并按 Delete / Backspace 移除；Tag 本体不可聚焦，仅 `×` 按钮独立进入 Tab 序列。

### 3.2 弹窗标准

弹窗统一使用平台标准弹窗，不得在业务页面重新搭建遮罩、定位、标题栏或底部操作区。

| 规格 | 宽度 | 适用场景 |
| --- | ---: | --- |
| `sm` | 420px | 确认、删除、单一短任务 |
| `md` | 560px | 标准表单、创建或编辑 |
| `lg` | 720px | 多段表单、小型数据列表 |
| `xl` | 900px | 大型列表、对比、可展开详情 |

- 默认最大宽度为 `calc(100vw - 48px)`，最大高度为 `calc(100vh - 48px)`；窄屏不得超出视口。
- 弹窗圆角统一 16px，遮罩使用 `overlay` 语义色，阴影使用 `--ds-shadow-dialog`。危险弹窗也保持中性外边框，不使用整圈红色边框。
- 标题统一使用 18px / 600；禁止在标题左侧放图标，右侧只保留关闭按钮。
- 标题描述是可选项，非必要不显示。只有需要在任务开始前说明系统行为、输入结果或操作范围时，才使用一行 12px 描述；禁止重复标题或堆叠多行帮助文字。
- 具体风险、影响数量、校验错误和表单字段帮助属于正文内容，应放入 Body 的提示区、字段帮助文字或危险信息条。
- Header 高度由 18px / 600 标题、可选描述和内边距自然撑开，不设固定 64px；默认上内边距 24px、下内边距 20px、左右间距 24px。Body 左右间距 24px；Footer 右对齐，与正文共用同一对齐线。
- Header、Body 与 Footer 依靠固定内边距和留白形成层级；弹窗壳内部不绘制 Header 下边线或 Footer 上边线。正文确有分区需求时，只在 Body 内使用单条弱分割线。
- 弹窗内的 Input、Textarea 和 Select 统一使用 `surface` 底与中性灰色描边；Hover 只加深边框，Focus 使用主题色 Focus Ring。页面搜索框可继续使用弱填充背景。
- **滚动权威规则**：高度超出时只允许 Body 滚动，Header 与 Footer 必须固定；列表型弹窗的局部列表可再设内部最大高度。其他章节只引用本条，不重复定义。
- Footer 操作顺序为“次要 / 取消”在左、“主要 / 确认”在右；只有关闭动作时使用普通次要按钮。
- Footer 主操作数量遵循 §13.1.1；删除等危险操作使用 danger 按钮并提供明确后果说明。取消发布、停用等可恢复的状态回退使用品牌主按钮；Warning 仅用于提示信息或状态标记，不能因为弹窗包含提醒文案就改用黄色确认按钮。
- 弹窗类型统一使用同一套中性壳、标题栏、关闭按钮和 Footer：提示用于可恢复状态回退；警示用于未保存修改、风险前置说明，确认仍为品牌主按钮；删除用于不可恢复动作，只有确认按钮使用 danger 语义。不得为不同类型新增黄色背景、整圈状态描边或标题左侧图标。
- 列表型弹窗优先使用分段切换 + 单层列表 / 折叠列表，禁止在展开区再套完整表格或多层卡片。
- 关闭与未保存保护分别遵循 §16.0 和 §27.17，本节不另行定义关闭分支。

## 4. 业务组件

- 设备卡片、状态卡片、数据面板、配置面板和图表容器必须建立独立业务类，不得复制页面内联样式。
- 业务组件只能组合基础组件和 Token，不得覆盖基础组件的核心状态规则。
- 卡片必须预留异步内容空间，避免 Loading 完成后发生布局跳动。
- 状态不能只用颜色表达，必须同时使用文字、图标或形状。
- 3D、图表等深色内容区属于独立 Scene Scope，不得反向污染普通页面主题。工业风 3D 视口在 Light / Dark 下都使用近黑场景底（基准 `#101316`），网格、坐标轴、遥测文字和 HUD 必须使用场景专属高对比 Token；页面 Light/Dark 切换不得把 3D 画布改成浅色。

## 5. 页面模板

页面模板解决整体布局；基础组件和业务组合解决局部一致性。模板及页面级状态的完整规则见第 20 节。

- 新页面优先使用 `.ds-page--list/detail/form/config/dashboard/workflow/workbench/editor/split` 模板类；不得由业务页面重新定义页面外边距、主体滚动策略或固定操作区。
- Modal Form 与 Drawer Detail 使用第 3.2 节的浮层壳，只定义 Header、Body、Footer 中的业务内容。

## 6. 响应规则

- ≥1200px：完整导航与多栏布局。
- 768–1199px：减少页面边距和侧栏宽度，优先保持主任务区。
- <768px：多栏改纵向；侧栏宽度变 100%；页面边距 16px。
- 内容溢出时先压缩可伸缩区域，再启用内部滚动，不允许正文被裁切。
- 表格在窄屏可横向滚动或转卡片；操作列不得被遮挡。
- Hover 入口在触屏设备必须常显或有等价点击入口。

## 7. 状态规则

- Normal：信息层级清晰，不使用多余高亮。
- Hover：只改变颜色、背景、边框或阴影，不改变占位尺寸。
- Pressed：只在按压过程中可见；Selected：点击完成后持续可见，两者都必须与 Hover 有明显区别。
- Focus：所有键盘可操作组件必须显示可见 Focus Ring，尺寸与偏移统一见 §12.3。
- Disabled：降低透明度、显示不可用光标，并阻止事件。
- Loading：按钮显示 Spinner；内容区优先 Skeleton，并保留最终尺寸。
- Empty：说明为什么为空，并在可执行时提供下一步操作。
- Error：说明问题与恢复方式；危险色不能作为唯一信息。
- 动效默认 120–240ms，并遵守 `prefers-reduced-motion`。

## 8. 开发约束

- 新页面不得新增大段 `<style>` 内联样式；通用样式进入设计系统，业务样式进入对应业务组件样式文件。
- 内联样式仅允许动态几何值、运行时坐标、图表数据或一次性计算结果。
- 新增基础控件前，先确认平台现有规范与团队组件库是否已覆盖需求；存在时必须复用，不得以不一致的自定义控件替代。
- 新增业务页面不得引入与平台视觉规范冲突的基础控件样式；存量页面按迁移计划逐步收敛。
- UI 提交验收至少检查：主按钮唯一、Tag 无描边、Label 可见、键盘 Focus 可见、Light/Dark 正常、Normal/Loading/Empty/Error/Disabled 状态完整。
- 改动后必须执行 `npm run build` 与 `git diff --check`。
- 每次新增组件前，先确认现有基础组件或业务组件是否已覆盖需求。

## 9. 已发布设计 Token 对照

本节仅摘录当前设计系统已发布的 Token，未列出的数值不得自行补充为全局规范。

### 9.1 语义颜色与主题

- 页面、布局、表面、弱背景、边框、标题、正文、辅助文字分别使用 `--ds-color-page`、`--ds-color-layout`、`--ds-color-surface`、`--ds-color-soft`、`--ds-color-border`、`--ds-color-heading`、`--ds-color-text`、`--ds-color-muted`。
- 实色主按钮使用 `--ds-button-primary-bg`（Current 对应 Light `#241F7D` / Dark `#4F46E5`）与 `--ds-button-primary-text`；`--ds-color-accent` 用于已选文字、Focus 与暗色高亮，不得替代主按钮背景。状态使用 `--ds-color-success`、`--ds-color-warning`、`--ds-color-danger` 及对应的 `*-soft` / `*-text` Token。
- 当前主题系统仅发布 light / dark 两套语义值；页面不得直接取用调色板中的十六进制色值。

### 9.2 尺寸、圆角与阴影

| 阴影 | `none` / `xs` / `sm` / `card` / `overlay` / `dialog` |
| 动效时长 | 120 / 160 / 240ms |

### 9.3 已发布基础控件尺寸

| 控件 | 已发布值 |

| Tag | 默认 24px 高、水平内边距 12px；紧凑态 20px 高、水平内边距 8px；两种尺寸均使用 12px 文字和胶囊圆角 |
| Table | 表头 44px，数据行 60px |
| Modal | 四档宽度及适用场景见 §3.2；最大尺寸为视口减 48px |

### 9.4 布局与响应值

- [ ] 页面使用 light / dark 主题语义 Token，不直接写死普通界面的颜色值。

## 11. 已实现交互契约

本节描述当前系统已经实现的交互行为。新增页面或改造现有页面时，应沿用这些行为；未在本节列出的交互不应直接作为全局规则扩展。

### 11.1 可交互元素状态

- 可点击的通用元素使用统一状态契约：基础层仅负责 Hover/Pressed/Selected 的 Token、过渡、Focus Ring、Disabled 和 Loading 事件约束；具体背景、边框和文字颜色由所属组件 Token 决定。
- Disabled 状态引用 `--ds-opacity-disabled`、禁用光标并阻止指针事件；具体数值以第 1 节 Token 为唯一来源。Loading 状态使用进度光标并阻止重复点击。
- 按钮的局部 Loading 外观由组件契约定义；防重入、时序与结果反馈统一见 §27.9。
- 当系统启用“减少动效”偏好时，交互元素、树节点和菜单的过渡与动画必须关闭。

### 11.2 弹窗与确认

- 弹窗关闭入口、状态回收与焦点返回统一见 §16.0；本节只记录当前实现已接入该契约。
- 删除等危险操作使用危险语义的确认按钮；取消和确认并列展示，取消不应执行任何数据变更。
- 表单型弹窗的确认按钮可在必填信息不完整时禁用；字段错误在字段附近展示，不以单纯颜色替代提示。

### 11.3 展开、选择与筛选

- 可展开的树节点、折叠区域和下拉入口使用 `aria-expanded` 表达当前开合状态；视觉指示与状态同步变化。
- 二选一或多选筛选项使用 `aria-pressed` 表达已选状态；列表选项使用 `aria-selected` 表达选中状态。
- 当前已实现的可搜索选择器在输入聚焦或内容变化时展开候选项；选中候选项后关闭，在焦点离开整个控件时关闭。候选项区域可滚动，避免撑开页面。

### 11.4 表单、图标操作与反馈

- 字段通过可见 Label 或 `aria-label` 提供名称；纯图标操作必须提供 `aria-label`，并在现有界面中配合标题提示。
- 可快速提交的现有输入场景支持 Enter；重命名场景支持 Escape 关闭。其他输入场景不得默认推断或强制绑定这两个按键。
- 校验错误使用字段附近的错误文本和 `role="alert"`；状态、错误、选中不能仅依赖颜色。
- 成功保存、刷新和复制等操作沿用对应页面现有的局部状态反馈方式，避免在同一页面新增不同的反馈样式。

### 11.5 图标规范

- 图标统一使用项目已批准的**线性系统图标库**；同一页面不得混用不同风格、不同圆角语言或不同描边粗细的图标。面性图标只可作为既有品牌资产或明确的业务插画，不能与线性操作图标并列混用。
- 标准尺寸为：12px 用于紧凑状态标记；14px 用于 24px 控件；16px 用于 32 / 40px 常规控件；20px 用于页面级操作或空状态辅助；24px 用于模块级图标。除这五档外不得新增页面私有尺寸。
- 线性图标统一使用 `24 × 24` viewBox 和 1.8px 描边；自定义 SVG 必须移除硬编码 fill / stroke，使用 `currentColor`，并在导入前按该 viewBox 和描边规则校正。
- 常规功能图标默认继承相邻文字色或 `--ds-icon-color`；按钮内图标继承文字色。成功、警示、错误等状态图标分别使用对应语义色，且必须配合状态文字，不能只依赖颜色。
- 方向语义统一：向右表示进入、下一步或展开的目标方向；向下表示展开；向上表示收起；向左表示返回；同一页面不得让同一方向表达相反含义。左右、上下方向图标不作镜像替换来表达不同业务含义。
- 装饰图标不得使用品牌主色抢占主操作层级；图标不能替代含义不明确的文字。纯图标操作仅用于高频且图标含义明确的动作，并提供 `aria-label` 与 Tooltip。
- 业务专属图标应先归类为对象、状态或功能图标；不能以随机 Emoji、彩色图片或临时 SVG 代替系统图标。新增图标须经过设计评审并加入统一资产清单。

### 11.6 内容文案规范

- 文案以用户任务、对象和结果为中心，优先使用明确动词：使用“保存配置”“创建型号”“重新加载”，避免“确定”“提交”“处理”等脱离上下文的泛化词。
- 页面标题表达当前对象或任务；按钮表达下一步动作；状态表达“对象 + 当前结果”；错误说明包含问题与可执行修正方向。相同概念在同一产品内使用同一名称，不混用同义词。
- Placeholder 只给输入示例，不重复 Label，也不承载必填、格式、范围或错误规则；这些信息使用 Label、帮助文本和错误文本表达。
- 成功、错误、空状态和无权限文案必须同时给出可理解的原因或下一步；不显示内部接口名、错误码、堆栈或“操作失败，请重试”这类无上下文提示。
- 日期、数字、版本号、文件名和单位使用统一格式；数值与单位、状态图标与状态文字不可拆行。中英文、数字与标点之间遵循同一页面既有格式，不为视觉凑字新增空格或换行。
- 文案优先简短、单义、可扫描；长说明放入帮助文本、详情或 Tooltip，Tooltip 不能承担唯一关键说明。危险操作必须说明影响对象和不可恢复后果。
- 列表、看板等管理页顶部不得放置常驻功能说明条或联动说明；此类信息仅在对应操作处需要时出现（字段帮助文本、Tooltip、空状态或详情页），避免在页面堆叠与当前任务无关的引导文案。

### 11.7 交互验收

- [ ] Hover、Pressed、Selected、Focus、Disabled、Loading、Readonly、Error、Success 的视觉和事件行为符合第 11.1 节。
- [ ] 弹窗的四种关闭入口均能正确收口；危险确认不会由取消入口触发。
- [ ] 展开、选中、筛选和图标操作具有对应的可访问状态或名称。
- [ ] 图标尺寸、描边、颜色、方向与自定义 SVG 均符合第 11.5 节；页面未混用多套操作图标风格。
- [ ] 标题、按钮、状态、错误与空状态文案符合第 11.6 节，且未以 Placeholder 或 Tooltip 承载唯一关键信息。
- [ ] 可搜索选择器在打开、选择、失焦关闭和候选项滚动时行为正确。
- [ ] 开启“减少动效”偏好后，不保留非必要过渡或动画。

## 12. 组件状态模型

### 12.1 统一命名与代码映射

`Active` 禁止再作为通用状态名称。它同时可能表示鼠标按压、当前页面、Toggle 打开或菜单高亮，无法形成可靠的设计、代码和测试映射。统一使用下表。

| 规范状态 | 定义 | 推荐代码映射 |
| --- | --- | --- |
| Default | 未被操作的基础状态 | 默认样式 |
| Hover | 指针位于有效热区 | `:hover` |
| Pressed | 指针或键盘仍处于按下过程 | `:active`、`data-state="pressed"` |
| Focus | 获得键盘焦点 | `:focus-visible`、`data-state="focus"` |
| Selected | 点击完成后持续选中 | `aria-selected="true"`、`data-selected="true"` |
| Checked | 勾选或开关值为真 | `aria-checked="true"`、`data-checked="true"` |
| Open | 下拉、菜单或浮层已展开 | `aria-expanded="true"`、`data-state="open"` |
| Expanded | 树、折叠面板已展开 | `aria-expanded="true"` |
| Disabled | 当前不可操作 | 原生 `disabled` 或 `aria-disabled="true"` |
| Loading | 正在等待异步结果 | `data-state="loading"` |
| Readonly | 可查看/复制、不可编辑 | `readonly`、`aria-readonly="true"` |
| Error | 校验或请求失败 | `aria-invalid="true"`、`data-state="error"` |
| Success | 操作完成后的结果反馈 | `data-state="success"`、状态文字或提示条 |
| Empty | 数据、搜索或筛选结果为空 | 空状态容器与下一步操作 |

`Pressed` 是瞬时状态：按下开始、释放或取消即结束。`Selected` 是持续状态：例如当前 Tab、已选菜单项、已选表格行；两者可以组合为 `Selected + Pressed`，但不能互相替代。

### 12.2 状态组合与收敛规则

状态不是单一优先级链。以下四类可以同时存在，组件只实现适用项：

| 类别 | 状态 | 收敛规则 |
| --- | --- | --- |
| 可操作性 | Disabled、Loading、Readonly | Disabled 阻止一切交互；Loading 默认阻止重复提交；Readonly 保留查看、选择和复制能力，但不允许修改。 |
| 瞬时交互 | Hover、Pressed、Focus | Pressed 只在按压期间有效；Focus 必须在 Error、Selected 等状态上继续可见。 |
| 持续选择 | Selected、Checked、Open、Expanded | 这些状态可与 Hover、Pressed、Focus 组合；Selected + Hover 以 Selected 为底色，不退回普通 Hover。 |
| 结果与内容 | Error、Success、Empty | Error 与 Success 是结果反馈，不替代 Focus 或选择状态；Empty 是内容状态，不应用于单个交互控件。 |

- `Disabled` 覆盖其他交互反馈，事件处理函数也必须提前返回；仅 CSS `pointer-events: none` 不足以阻止键盘和程序调用。
- `Error + Focus` 必须同时保留：错误边框传达错误语义，Focus Ring 传达键盘位置。
- `Open` 用于触发器和浮层之间的持续关联，关闭后恢复 Default 或 Selected。
- `Success` 必须有可读文本或可感知提示；它不等同于绿色的 Hover、Pressed 或 Selected。

### 12.3 基础状态行为

- Hover、Pressed、Focus 和 Selected 的状态切换不得改变控件占位尺寸、文本换行或页面布局。
- Hover 不能承载唯一操作；触控端必须提供常显或可点击的等价入口。
- Pressed 必须即时响应，不使用延迟、弹跳或大幅缩放；可使用颜色加深、阴影收缩或最多 1px 的内容位移。
- Focus Ring 为 2px，偏移为 2px，必须在周边背景上可辨识；不可通过 `outline: none` 移除后不提供替代。
- **全局约束：颜色不是唯一状态**——所有状态（错误、成功、选中、禁用、告警）不得仅依赖颜色传达，必须配合文字、图标、形状或 ARIA 属性中的至少一种。（下文各节重复此约束时以本条为权威定义。）
- **Error 状态最低要求**（适用所有组件与页面，各节不再重复，仅引用）：① 用可理解的语言说明发生了什么，不显示 HTTP 状态码或内部报错；② 说明影响范围；③ 提供至少一个可执行动作（重试 / 返回 / 申请权限）；④ 错误信息使用 `role="alert"` 或 `aria-live="assertive"` 播报；⑤ 错误状态图标必须配合错误文字，不只依赖红色。

## 13. 已发布组件 Token 与组件契约

组件只能消费 `tokens/design-tokens.json` 发布的组件 Token。前端可将其转换为 CSS Variables 或组件库主题对象，但业务页面不得直接写各状态色值或重新创造同义变量。

| 组件 | Token 前缀 | 必须覆盖的状态 |

| Select | `--ds-input-*`、`--ds-select-*` | Default、Hover、Pressed、Focus、Filled、Open、Selected、Disabled、Loading、Error |
| Checkbox | `--ds-checkbox-*` | Default、Hover、Focus、Checked、Indeterminate、Disabled、Readonly |

| Tabs | `--ds-tabs-*` | Default、Hover、Pressed、Focus、Selected、Disabled |
| Menu | `--ds-menu-*` | Default、Hover、Pressed、Focus、Selected、Disabled、Open/Expanded |

### 13.1 Button、ToggleButton 与 IconButton

#### 13.1.1 使用边界

- `Button` 用于保存、创建、确认、刷新和提交等一次性动作，只含 Default、Hover、Pressed、Focus、Disabled、Loading；**普通 Button 没有 Selected**。
- `ToggleButton` 用于网格／列表视图、吸附开启等持续选择，包含 Default、Hover、Pressed、Focus、Selected、Disabled；使用 `aria-pressed` 表达状态。
- `IconToggleButton` 仅用于图标语义明确的高频持续选择，状态同 ToggleButton，必须有 `aria-label` 和 Tooltip。
- 类型只允许 `primary`、`secondary`、`outline`、`text`、`danger`；一个操作区域最多一个 `primary`。“操作区域”指同一 Toolbar、Modal / Drawer Footer、表单提交区或同一就近决策按钮组，不跨独立容器合并计算。`danger` 是风险语义，不等同于 Pressed、Error 或 Selected；删除、解绑等不可逆操作必须二次确认。

#### 13.1.2 Primary 与 Secondary 状态矩阵

所有状态均须明确 background、text、border、icon、shadow、focus ring、cursor、opacity 与 transition；图标始终继承 `currentColor`。

| Primary Hover | `--ds-button-primary-bg-hover` | Default | `--ds-button-primary-border` | `--ds-button-primary-shadow-hover` | 无 | pointer | 1 | 同上 |

| Primary Disabled | `--ds-button-disabled-bg` | `--ds-button-disabled-text` | `--ds-button-disabled-border` | none | 无 | not-allowed | `--ds-opacity-disabled` | 同上 |
| Primary Loading | 保持触发前类型 | 保持触发前类型；Spinner 使用 currentColor | 保持触发前类型 | 保持触发前类型 | 无 | progress | 1 | 同上 |

#### 13.1.3 内部规格与内容结构

| 规格 | 24px / 32px / 40px | Token |
| --- | --- | --- |
| 水平内边距 | 8 / 10 / 14px | `--ds-button-padding-inline-*` |
| 最小宽度 | 48 / 56 / 64px | `--ds-button-min-width-*` |
| 最大宽度 | 常规按钮不设全局最大值；不得超过所在操作区。`fullWidth` = 容器可用宽度 | 布局约束 |
| 文字 | 12 / 12 / 14px；行高 1；字重 600 | `--ds-button-font-size-*`、`--ds-button-line-height`、`--ds-button-font-weight` |
| 图标与图文间距 | 按组件尺寸 Token 映射；见 §11.5 | `--ds-button-icon-size-*`、`--ds-button-icon-gap` |
| 边框与 Spinner | 1px；14px / 2px 描边 | `--ds-button-border-width`、`--ds-button-spinner-*` |

允许纯文字、前置图标＋文字、文字＋后置图标、纯图标、Loading 图标＋文字五种形态。普通动作图标默认前置；展开、跳转类图标可后置；同一按钮不得同时出现前后两个图标。纯图标只用于高频且含义明确的操作。文案默认单行，过长时优先缩短文案或收进 More，不得在按钮内换行。常规 Button 不发布固定最大宽度，宽度由内容与内边距决定且不得超出所在操作区；`fullWidth` 只用于窄栏表单、固定底部操作等通栏任务，并等于容器可用宽度。Loading 前后保留同一宽度，不得因文案变化跳动。

#### 13.1.4 IconButton

- 高度只允许 24 / 32 / 40px；视觉尺寸可为 24px，但鼠标热区至少 32×32px、触控热区至少 44×44px。
- 纯图标按钮必须有 `aria-label` 和 Tooltip；Loading 时保持原宽度并阻止重复触发。

### 13.2 SearchInput 与 SearchBar

- `SearchInput` 用于在当前数据集内按关键词查询；默认高度 40px，搜索图标 16px。**默认实时搜索**：输入变化立即更新结果，不设置独立的“查询”或“筛选”提交按钮。
- 有内容时提供清除入口；清除后恢复完整结果。Loading 在输入框尾部展示，保留已输入关键词与控件宽度。
- `SearchBar` 可由 SearchInput、主筛选条件、重置操作和结果反馈组成。搜索词或筛选值变化后都应直接更新结果，不再增加独立的“筛选”提交按钮。
- 有关键词时显示清除入口；“重置”同时恢复搜索词和所有筛选条件。
- 主筛选条件只保留 1–2 个高频项；更多条件收进独立 FilterPanel / Drawer，避免挤压 SearchInput。
- 搜索词不得只用 Placeholder 表达字段含义；没有可见 Label 时必须提供可访问名称。无结果时保留搜索词，并提供清除入口。

### 13.3 Input、InputNumber 与 Select

- Input、TextArea、Select 都必须有可见 Label；Placeholder 仅用于输入示例，不能代替字段名称。
- Readonly 保留正常文本对比度并允许复制；Disabled 不可编辑、不可聚焦，并在需要时通过外层 Tooltip 解释原因。
- **Readonly 字段的复制行为**：默认允许用户自行选中并复制，不强制提供复制 IconButton。若业务需要一键复制（如 API Key、编号），则在字段尾部放 16px CopyIcon IconButton；点击后触发 `navigator.clipboard.writeText`，成功后 Icon 临时切换为对勾图标（1.5 秒）或显示短暂 Tooltip“已复制”；失败时静默回退，不弹错误 Toast。
- Select 的触发器在 `Open` 时保持 Focus/品牌边框；选项使用 `aria-selected`，多选筛选项使用 `aria-pressed` 或 `aria-checked`。
- 可搜索 Select 输入变化后打开候选列表；`Esc`、点击外部、焦点离开整个控件或完成选择后按产品规则关闭。选项过多时列表内部滚动，不得撑开页面。
- `InputNumber` 仅用于有明确数值含义、单位、范围或步长的字段；键盘输入、上下键、步进按钮使用同一 `min / max / step` 校验，禁止让三种方式得到不同结果。
- 数值与单位不可分离；步进按钮不能是唯一输入方式。范围、精度、单位和非法输入提示应在字段附近说明；Loading、Error、Readonly、Disabled 沿用 Input 状态规则。
- **Input / TextArea 的 Loading 状态**：异步校验期间，在字段右侧尾部显示 16px Spinner，输入保持可用但校验行为挂起；控件宽度和高度不得因 Loading 改变；Loading 结束后恢复 Default 或直接进入 Error 状态。
- **Select 的 Filled 状态**：已选中值时，占位文字替换为选中 Label（使用 `--ds-color-heading` 或 `--ds-color-text`）；有清除入口时在触发器右侧显示清除 IconButton；触发器外观与 Default 相同，不因有值而变色；清除后将值设回 null 并自动恢复 Default 外观。

### 13.4 Radio、Switch 与 Checkbox

- `Radio` 用于少量互斥选项；选项必须始终可见且可比较。当前值使用 `aria-checked`，键盘方向键在同组内移动；选项过多、需要搜索或分组时改用 Select。
- `Switch` 用于开/关立即生效的独立设置；切换后如需要异步保存，应在控件附近反馈保存中、成功或失败，并在失败时恢复或明确保留原值，不能把 Switch 当作表单提交前的多项选择。
- **Switch 的 Loading 状态**：切换后立即锁定开关，在开关右侧或内部显示 Spinner；Loading 期间阻止再次切换；成功后更新状态，失败时恢复原值并在字段附近显示错误提示（不弹 Toast）。
- Radio 和 Switch 的标签是完整热区的一部分；Disabled 必须说明原因（需要时用外层 Tooltip），Checked 与 Focus 可同时可见。

- Checked 使用品牌色底和品牌描边，勾选图标使用 `accent-contrast` 反白色；不得继承正文灰或状态色。
- Disabled 使用 Disabled Token，可呈现灰色勾选图标；这只适用于不可操作状态，不能与正常 Checked 混用。
- 复选框及标签作为一个可聚焦操作项；Focus Ring 覆盖完整控件，Checked + Focus 同时保留。
- **Checkbox 的 Indeterminate 状态**：用于父级/全选 Checkbox 的部分选中。使用 `--ds-checkbox-indeterminate-bg` 和水平短线图标（非勾选图标）表达；可与 Focus 同时可见；勾选全部后恢复 Checked，取消全选后恢复 Default；不得与正常 Checked 混用。

### 13.5 Pagination

- Pagination 用于可分页的结果集合，默认单项尺寸 32px；当前页使用 Selected 语义，前后页不可用时 Disabled，不以 Hover 表达当前页。
- 分页位于结果区底部或列表 Footer；切换页后保留筛选和排序，内容区回到结果起点，并通过可访问状态告知当前页。
- 页码过多时收敛为首尾页、当前页邻近页与省略号；省略号不可点击。窄屏优先保留上一页、当前页、下一页和总数／跳页入口，不能挤压成不可读密度。
- **边界情况**：结果数量为 0 时不显示 Pagination，由空状态替代。仅 1 页时隐藏 Pagination 或保留但隐藏页码列表，仅保留总数文案（如“共 5 条”）；不显示不可交互的单个页码。

### 13.6 Tabs 与 Menu

- Tab 的当前项使用 `aria-selected="true"`，不是 `Active`；左右方向键在同组内移动，Enter/Space 激活。
- Menu 的当前页面或当前命令使用 `aria-current` 或 `aria-selected`；展开父级使用 `aria-expanded`。
- 菜单项 Hover 只表示可操作，Selected 才表示当前位置；收起导航中不得仅保留无说明图标。

## 14. 表单规范

### 14.1 字段结构与间距

每个字段按以下顺序组织：

```text
Label（必填标记）    Short description / Unit / Character count（可选）
Control
Help（可选）
Error message（可选）
```

- 限制字数、单位、是否必填等一行短说明放在 Label 右侧并两端对齐；该说明使用 12px 辅助文字且不得挤压 Label。
- 需要解释用户如何填写、错误原因或服务端校验结果的长说明放在 Control 下方，不得塞入 Label 右侧。
- Label 与 Control 间距 8px；Control 与帮助或错误文本间距 4px。
- 常规字段间距 16px；表单分组间距 24px。
- **表单 Section 标题全局规则**：表单内部的分组标题使用 14px / 600 / `--ds-color-heading`，与正文字号相同并以字重区分层级；16px 只用于模块级标题。仅当 Body 内分区确需边界时，标题下方使用 `--ds-color-border` 1px 分割线。
- 必填标记置于 Label 后，不能只依赖 Placeholder 或红色边框。
- 单列表单为默认；双列表单只用于字段短、编辑任务明确且宽度充足的场景。窄屏统一退为单列。
- Label 过长允许最多两行；数值与单位不可拆开，单位优先置于控件后缀或字段帮助中。

### 14.2 校验与提交

- 必填、格式和范围可在失焦或提交时校验；异步唯一性校验需要说明“校验中”状态。
- Error 必须保留用户输入内容，并在字段附近显示可执行的修正说明，使用 `role="alert"`。
- 提交时定位第一个错误字段；当错误字段不在可视区时滚动到该字段并保持页面上下文。
- 提交按钮在请求中进入 Loading；成功后按页面规则关闭、重置或停留，不得静默改变表单。
- 关闭含未保存修改的表单、Drawer 或 Modal 时必须请求确认；取消确认不得修改数据。
- Enter 仅可在明确的短表单中提交；TextArea 中 Enter 默认换行，Esc 只用于已有明确取消语义的场景。
- 服务端字段错误必须映射回对应 FormItem；无法归属字段的错误显示在表单级错误摘要中。提交失败后保留全部已填值、滚动并聚焦第一个无效字段，不得清空表单。
- 异步校验、联想和搜索必须防抖并取消过期请求；只接收最后一次输入对应的响应。中文、日文等输入法处于 composition 阶段时，不得提前提交搜索或触发最终校验。
- 字段依赖变化后，必须清理已经无效的子字段、候选项和服务端错误，并按依赖顺序重新校验；不得提交界面上已隐藏的陈旧值。
- 粘贴、前后空格、全角字符、浏览器自动填充和密码管理器行为必须在字段契约中声明。标准身份、地址、电话和支付字段使用正确的 `autocomplete`，不得一律关闭。
- 数字、日期、时区和单位分别保存“提交值”与“显示值”。精度、舍入、空值和时区转换由领域规则确定，前端不得仅按格式化后的文本反解析业务值。
- 服务端返回冲突、权限变化或数据已过期时，应保留用户修改并提供刷新、覆盖、另存或重新授权中的有效动作；不得将所有失败统一提示为“保存失败”。

### 14.3 FormItem 状态矩阵

| 状态 | 视觉与行为 |
| --- | --- |
| Default | 中性描边、正常 Label、可输入 |
| Hover | 仅加强描边或弱背景，不代替 Focus |
| Focus | 品牌描边 + Focus Ring，光标可见 |
| Filled | 内容可见，可按需显示清除按钮 |
| Error | 错误描边 + 错误说明；获得焦点时保留 Error 语义和 Focus Ring |
| Readonly | 正常文字、不可编辑、可选择复制 |
| Disabled | 降低可用性提示、不可输入或聚焦；必要时给出禁用原因 |
| Loading | 异步候选、上传或校验显示局部进度，尺寸不跳动 |

## 15. Table、列表与数据操作规范

### 15.1 结构与内容

- 表头 44px、数据行 60px；数字、金额和百分比右对齐，文本和状态按列语义对齐。
- 表格边框分为五级 Token：`--ds-table-outer-border`、`--ds-table-header-divider`、`--ds-table-row-divider`、`--ds-table-column-divider`、`--ds-table-fixed-divider`。`--ds-table-border` 仅作为兼容旧名，新代码不得继续使用。
- 默认只显示横向分隔：表头底线比数据行线强一级，数据行使用低对比分隔线，最后一行不再绘制底线。普通列默认不画竖线。
- 仅在固定列、列分组或严格网格编辑表中允许列分隔线；固定列优先使用背景差和轻阴影，确需分隔时使用 `--ds-table-fixed-divider`。
- 表格外框与页面容器边框不得重复：独立 TableSurface 使用外框，全宽嵌入卡片的表格由卡片承担外框，表格自身设为无外框。
- 表格模块标题使用 16px / 600 / `--ds-color-heading`；表头使用 12px / 500 / `--ds-table-header-color`（解析为正文高对比色），不使用 600 或更高字重，也不得用 Placeholder/Disabled 灰表达表头。
- 普通单元格使用 14px / 400 / `--ds-color-text`；名称、编号、版本等主标识单元格可使用 14px / 500 / `--ds-color-heading`，不得将整行或整表设为中粗。
- 时间、描述、补充状态等辅助信息使用 12px / 400 / `--ds-table-cell-secondary-color`；该 Token 必须满足正文对比度，不能直接复用 Disabled 色。数字使用 14px / 400、右对齐和 `tabular-nums`。
- 业务页面必须引用 `--ds-table-title-*`、`--ds-table-header-*`和 `--ds-table-cell-*` 文字 Token，不得根据风格预设重新定义字号或字重。
- 长文本单行省略，并通过 Tooltip 或详情入口呈现完整值；主标识列可按需要固定在左侧。
- **操作列全局规范**：操作列固定在右侧，基准宽度 96px（容纳最多 3 个 32px IconButton + 8px 间距）；超过 3 个操作时多余操作收进 Dropdown“更多”。操作列宽度不因语言扩展，所有 IconButton 依赖 `aria-label` 和 Tooltip，不使用文字。
- 宽表使用表格容器内部横向滚动；页面主体不因表格产生横向滚动。窄屏可切换卡片列表，但必须保留关键字段和主要操作。
- 行点击、复选框和行内按钮必须各自处理事件；行内操作不得意外切换行选中，除非业务明确要求。

### 15.2 状态与行为

| 场景 | 规则 |
| --- | --- |
| 排序 | 可排序表头 Hover 显示排序入口；当前排序列显示方向和优先级，重复点击在升序/降序/默认间循环。 |
| 筛选 | 筛选条件在工具栏或表头统一展示；已生效条件可见、可逐项清除，清空后恢复默认数据集。 |
| 行 Hover / Pressed | Hover 使用 `--ds-table-row-bg-hover`；Pressed 仅在鼠标按下期间使用 `--ds-table-row-bg-pressed`。 |
| 行 Selected | 使用 `aria-selected` 或复选框状态，持续使用 `--ds-table-row-bg-selected`；Selected + Hover 不退回普通 Hover。 |
| 展开行 | 用 `aria-expanded` 标识；展开内容与主行关联，缩回时恢复原行高度。 |
| 展开行内容状态 | 展开后子区域使用固定最小高度的 Skeleton 或局部 Spinner；请求失败时在子区域内显示简短说明与重试按钮，不折叠父行，也不显示整行红色背景。 |
| 批量操作 | 选择至少一行后出现批量操作栏，必须显示已选数量；清除选择可恢复原工具栏。 |
| Loading | 首次加载使用 Skeleton 或固定高度 Loading；局部刷新保留已有内容并显示局部进度。 |
| Empty | 区分“尚无数据”和“筛选无结果”；后者提供清除筛选，前者在可创建时提供下一步操作。 |
| Error | 说明加载失败原因并提供重试；不可只显示红色图标或空白表格。 |

### 15.3 高级数据行为

- 全选必须明确作用域：当前页、当前筛选结果或全部结果三者只能选一种，并在批量操作栏中写出范围与数量。跨页选择不得因翻页静默丢失；筛选条件改变时应确认是否清空既有选择。
- 禁用行可被读取但不可被选择或执行行操作，并通过说明文字、Tooltip 或状态列解释原因；全选计算必须排除禁用行。
- 批量请求支持部分成功：成功项从选择集中移除，失败项保持选中并显示逐项原因，可只重试失败项。不得把部分成功伪装成全部成功或全部失败。
- 固定列在横向滚动开始/结束位置显示轻量阴影或 `--ds-table-fixed-divider`；固定区域背景必须不透明，不能让滚动内容穿透。
- 虚拟列表必须保留表头语义、键盘焦点、行选择和读屏所需的总行数/当前位置；动态行高需测量并缓存，不允许滚动时反复跳动。
- 列宽、显示/隐藏、顺序和密度可持久化时，必须按用户与表格标识隔离；表结构升级后迁移或清理不兼容偏好，并提供“恢复默认”。
- 行内编辑应有明确的保存/取消边界；离开编辑行、翻页、排序或关闭页面时处理未保存内容。服务端冲突只标记受影响单元格/行，不清空其他编辑结果。
- 排序、筛选、分页和刷新都必须能够由服务端驱动；请求参数、URL 状态、结果总数与可见控件保持一致，过期响应不得覆盖较新的查询结果。

## 16. 浮层与反馈规范

全局浮层由平台基础控件负责 Portal、层级、视口碰撞、焦点和关闭行为；业务页面不得自行创建同类遮罩或 z-index。

### 16.0 统一关闭行为（全局权威定义）

以下规则适用于全部浮层类型，各节不再重复，仅引用本条。

1. **关闭入口**：所有浮层支持以下任一方式关闭：触发器（如有）再次点击 / 右上角 `×` 按钮 / `Esc` / 点击遮罩（危险或含未保存内容时见第 2 条）/ Footer"取消 / 关闭"；各入口必须使用同一套关闭逻辑，状态统一回收。
2. **含未保存内容的表单型浮层**（Modal / Drawer）：`Esc` / `×` / 遮罩点击均先进入"离开保护"确认对话框，提供「放弃修改」/ 「继续编辑」两个选项（若支持草稿可加「保存并离开」）；取消确认（"继续编辑"）后不修改任何数据，浮层恢复正常。
3. **非表单型浮层**（Dropdown / Tooltip / Popover）：点击外部或 `Esc` 直接关闭，无需确认；Tooltip 在 Hover/Focus 离开时自动关闭。
4. **焦点返回**：关闭后焦点统一返回打开该浮层的触发元素；若触发元素已销毁，回到同级容器标题或合理的上级容器。
5. **层级**：Dropdown 50、Drawer 60、Modal 70、Toast 80、Tooltip 90；弹窗内的 Select/Popover 使用 `modal-popover` 75，确保其位于所属弹窗之上但低于 Toast；业务代码不得新增任意 `z-index`。

**画布图层例外**：全屏编辑器（`.ds-page--editor`）的画布内部元素可以使用业务数值层级，但层级作用域必须限制在画布容器内；画布父容器使用 `isolation: isolate` 或等价的新建层叠上下文，任何画布图层不得越界覆盖页面导航、Modal、Drawer、Toast 或 Tooltip。

| 组件 | 用途 | 必须行为 |
| --- | --- | --- |
| Tooltip | 一句短说明；纯图标操作的补充 | 不承载唯一操作；Hover/Focus 显示，Esc 或失焦关闭；最大宽度 `--ds-tooltip-max-width`。 |
| Popover | 少量解释、预览或轻量操作 | 触发器用 `aria-expanded`；点击外部和 Esc 关闭；内部可有少量操作，不用于长表单。 |
| Dropdown | 命令或选项列表 | 键盘上下移动、Enter 执行、Esc 关闭；危险项独立语义。 |
| Drawer | 保留当前页面上下文的连续配置、详情 | 结构与滚动见 §3.2；关闭见 §16.0；未保存保护见 §27.17。 |
| Modal | 独立短任务或高风险确认 | 结构、尺寸与滚动见 §3.2；焦点、关闭与层级见 §16.0。 |
| Toast | 短暂、非阻塞的操作结果 | 不放关键长文本；成功/失败都要有文字，避免连续重复弹出。 |
| Notification | 需要保留、可行动或多行的信息 | 支持关闭和明确下一步；宽度使用 `--ds-notification-width`，不替代 Modal。 |

- 反馈颜色必须表达语义：Info 使用 `accent / accent-soft`，Success 使用 `success / success-soft`，Warning 使用 `warning / warning-soft`，Error 与危险操作使用 `danger / danger-soft`；不得把所有反馈统一做成深色或同一种颜色。
- Toast/Notification 的状态图标使用对应语义色且不加装饰性圆形底框；背景使用对应 `*-soft` 状态面，描边使用同色低对比混合值。标题使用完整的语义文字色；说明使用“语义文字色 42% + Surface 58%”的低强调同色相，呈现明显更浅的红、黄、蓝或绿。说明不得与标题使用完全相同的高强调颜色，也不得退回不带语义倾向的纯中性灰；短反馈说明末尾不加句号。信息内容必须同时有图标、文字和可读状态。
- Toast 宽度为 `--ds-toast-width`（360px）：单行最小高度 `--ds-toast-min-height`（48px），标题加一行说明时最小高度 `--ds-toast-two-line-min-height`（64px），内边距为 12px 16px。Notification 宽度为 `--ds-notification-width`（420px），最小高度 `--ds-notification-min-height`（80px），内边距为 16px。两者均不设置固定高度，内容换行或出现操作时向下自然扩展。
- Toast 用于 360px 内的短结果，默认可自动关闭；Notification 用于 420px 内需要保留、重试或下一步操作的消息。两者均支持 Info、Success、Warning、Danger：Info 为品牌弱背景，Success 为成功弱背景，Warning 为警示弱背景，Danger 为错误弱背景；不得使用深色统一背景、灰色状态图标或“!”字符代替系统状态图标。
- Notification 的“重试”等行内操作使用 32px 高语义 Soft/Flat Button：默认采用约 20% 语义色填充和高对比语义文字，Hover/Pressed 逐级增强填充；不得使用透明底纯文字、铺满 Notification 高度或改成中性灰色块。
- **Undo Toast 变体**：用于可撤销的单项低风险操作（如临时删除）。使用 `--ds-toast-two-line-min-height` 最小高度；操作区使用 32px Soft/Flat 语义 Button“撤销”；倒计时以 Toast 底部 2px 进度条或文案（如“3 秒后删除”）之一表达，产品内全局统一一种；超时后 Toast 自动关闭且不可再撤销；点击“撤销”后 Toast 立即关闭并在列表原位置恢复对象。
- 浮层层级见 §16.0 第 5 条；Modal 业务内容不得使用 `bodyStyle` 改写平台发布的内边距、分区或滚动行为；复合选择器等特殊工作区需要无内边距时，必须使用已发布的 Modal 布局变体并保持唯一内部滚动容器。
- Tooltip、Popover、Dropdown、Select Popup 必须在视口碰撞时翻转或收缩；最大高度内滚动。
- 触控端 Tooltip 不得成为理解或操作的唯一入口；Drawer 和 Modal 在窄屏可采用近全屏样式。

## 17. 响应式、溢出与国际化

- 1200px 以下使用 12px 网格/模块间距，禁止 14px 响应式例外；768px 以下为单列并使用 12px 间距。
- 工具栏空间不足时保留页面主操作，次要操作收进 More；搜索与复杂筛选可折叠进入 Drawer。
- Tab 空间不足时采用横向滚动或 More，不允许挤压文字至不可读；Modal 在窄屏转为近全屏。
- 文件名、长英文、版本号允许省略但需可查看完整内容；数字与单位、日期与时区、状态图标与状态文字不得断行分离。
- 每个业务组件需声明紧凑、标准、展开三种容器适配策略，以及唯一的内部滚动容器。
- 日期、时间、数字、货币和单位使用 `Intl.DateTimeFormat`、`Intl.NumberFormat` 或等价的统一格式化层；不手工拼接年月日、千分位、货币符号和单位。
- 时间数据保存明确的瞬时值和 IANA 时区。界面同时涉及设备时区、用户时区或站点时区时必须标注当前显示口径；夏令时切换不得造成重复记录被误认为同一时刻。
- 文案不得通过字符串拼接组成句子；复数、性别、变量顺序和占位由国际化消息模板处理。按钮、Tab、表头和状态 Tag 至少按英文增长 30% 验收。
- 产品若承诺 RTL，导航、面包屑、步骤、排序图标、抽屉方向和 3D/图表工具栏均需镜像验收；若当前不支持 RTL，应在发布说明中明确，而非出现半镜像界面。

完整的语言声明、消息模板、组件适配、格式化、搜索排序、RTL 与验收要求见“26. 多语言与本地化规范”。

## 18. 版本管理与自动化验收

### 18.1 发布与变更

设计系统当前版本为 `1.7.0`，状态为 Active，适用 light / dark、desktop-web / pad-web。完整发布历史只维护在仓库根目录的 `CHANGELOG.md`，本文件不重复保存版本表。

- 新 Token、组件契约或废弃规则需要设计和前端共同评审。
- 破坏性变更必须提供替代 Token/组件、迁移期限和视觉回归截图。
- 组件状态标记为 Draft、Beta、Stable 或 Deprecated；业务页面只可依赖 Stable 组件，除非评审明确允许。

### 18.2 自动化验收

提交前执行：

```bash
npm run check
```

在独立规范仓库中，该命令会先校验并自动比对已解析 Token 文档，再验证：目录完整、五个发布版本一致、JSON 与 Token 引用可解析、主题和状态文字对比度、25 项组件契约字段完整、必需文档章节存在、Ant Design 适配器只引用已发布 Token。

在原型工程根目录执行同名命令时，还会检查规范到组件实现的映射并执行生产构建。前端项目接入后，应建立自己的实现映射、视觉回归和构建检查，不能把规范仓库校验当作页面验收的替代品。

人工视觉回归仍需覆盖 Light/Dark、desktop/pad、Default/Hover/Pressed/Focus/Selected/Checked/Open/Expanded/Disabled/Loading/Readonly/Error/Success/Empty、键盘操作与 `prefers-reduced-motion`。

### 18.3 前端交付物

- `docs/ui-guidelines.md`：规范与验收的唯一文字依据。
- `tokens/design-tokens.json`：light / dark、共享、状态和组件 Token 的机器可读唯一来源。
- `tokens/design-tokens-resolved.md`：由脚本生成的已解析 Token 表，供设计、研发和测试检索；禁止手工维护。
- `components/component-specs.json`：25 项基础组件的机器可读契约；包含用途与边界、参数、状态、关联 Token、无障碍、响应式、示例和验收项。
- `adapters/ant-design-theme.ts`：Ant Design 主题映射示例，可复制到前端工程后按实际依赖调整。

交付文件的使用边界和 Token 引用规则见 `docs/token-integration.md`。原型工程的样式文件仅用于维护原型，不作为前端项目的接入文件。

### 18.4 组件交付契约

`components/component-specs.json` 是组件规范的唯一机器可读来源；每个前端实现将其中的行为参数映射到团队已批准的基础组件，不能通过页面私有样式改写同一契约。

交互行为引用第 27 章的权威契约：异步操作见 §27.9，未保存离开保护见 §27.17，权限与占用见 §27.21。组件 JSON 只声明适用状态、参数、Token 与验收项，不复制整章流程规则。

| 类别 | 覆盖组件 |
| --- | --- |
| 通用 | Button、IconButton、Tag |
| 导航 | Tabs、Menu / Dropdown、Steps、Tree |
| 数据录入 | Input / TextArea、Select、DateTimePicker、Checkbox、Upload |
| 数据展示 | Table |
| 反馈 | Modal、Drawer、Tooltip / Popover、Toast / Notification、Empty / Loading / Error |
| 其他 | 按组件契约补充；未覆盖组件须先完成同等字段后才能进入 Stable。 |

每个组件契约必须完整包含以下内容：

- 用途、适用场景与不适用场景，避免将不同交互模式混用；
- 参数 / API 的名称、取值、是否必填和设计含义；
- Default、Hover、Pressed、Focus、Selected、Disabled、Loading、Error、Success、Read-only 等适用状态；不适用状态必须明确省略；
- 已发布 Token、键盘与读屏规则、响应式/溢出行为；
- 可复制的参考实现和可执行的验收项。

新增或修改组件时，必须同步更新契约、Token（如有）、主题映射、设计规范中心和静态验收；只改视觉预览或只改业务页面均不构成发布。

## 19. Vibe Coding 生成约束

```text
只使用已发布的 --ds-* Token 和平台基础组件；禁止硬编码普通页面颜色、圆角、阴影、间距和 z-index。

```

## 20. 页面模板、业务组合与页面级状态

### 20.1 模板通用骨架

每个页面模板都必须明确以下区域，未适用的区域应明确省略，不能由业务页面临时决定：

```text
Page
├── Header：面包屑（按需）、标题、说明、页面主操作
├── Toolbar：搜索、筛选、视图切换、批量操作或局部操作（按需）
├── Content：唯一的页面主滚动容器
└── Fixed actions / Pagination：固定提交区或分页（二者按模板适用）
```

- Header 的标题和说明在左，页面级主操作在右；同一 Header 最多一个主按钮。上下文操作、批量操作和行内操作不得挤入页面主操作区。
- Toolbar 位于 Header 与 Content 之间。筛选条件过多时保留高频条件，将次要条件收纳至 More 或 Drawer；筛选结果必须可见、可清除。
- `.ds-page__content` 或 `.ds-page__scroll` 是模板指定的唯一主滚动容器；表格、日志、画布等可声明自己的局部滚动容器，但不能使 `body` 产生业务内容滚动。
- 固定提交区使用 `.ds-page__fixed-actions`，仅用于保存、发布、下一步等完成当前任务的操作；需要分页的列表页将分页置于结果区底部，不能与固定提交区共用同一位置。
- Loading、Empty、Error、Permission 等页面级状态替换或覆盖 Content，不替换 Header 和已生效的筛选条件，除非页面已被删除或无权访问。

### 20.2 页面模板矩阵

| 模板 | Header / 主操作 | Toolbar、内容与分页 | 滚动与固定区域 | 空、错、加载及业务模式 |
| --- | --- | --- | --- | --- |
| 列表页 `.ds-page--list` | 左侧标题、结果范围或说明；右侧新建/导入等一个主操作。 | Toolbar 放搜索、筛选、视图切换；Content 为表格或卡片结果；分页在结果区底部。 | 结果区滚动；筛选和分页不随行内容横向滚动。 | 模式：查询、筛选、批量管理。无数据与无搜索结果必须区分；首次 Loading 使用结果骨架，刷新保留结果。 |
| 详情页 `.ds-page--detail` | 左侧对象名称、状态和摘要；右侧编辑、更多或危险操作。 | 无通用筛选和分页；主内容按信息分组，按需使用右侧摘要/操作栏。 | 主内容滚动；侧栏有独立滚动需求时只滚动侧栏自身。 | 模式：查看、判断、单对象操作。对象删除时保留 Header 上下文并将 Content 换为“内容已删除”状态和返回列表入口。 |
| 表单页 `.ds-page--form` | 左侧任务标题和必要说明；主操作在固定提交区，不放在 Header。 | 无分页；字段按分组组织，长表单可提供锚点导航。 | 表单主体滚动，提交区固定在底部。 | 模式：创建、编辑、申请。初始加载为字段骨架；保存 Loading 不清空填写内容；无权限时字段不显示可编辑态。 |
| 配置页 `.ds-page--config` | 左侧配置名称和状态；右侧仅放预览、更多等非提交操作。 | 左侧导航树或步骤，中间配置内容，按需右侧说明/校验摘要；无分页。 | 各栏独立内部滚动；提交区固定在配置内容底部。 | 模式：持续配置、发布。局部加载只替换对应配置分组；离线或只读时保留内容并禁用提交。 |
| 数据看板 `.ds-page--dashboard` | 左侧标题、时间范围或说明；右侧刷新、导出等全局操作。 | 全局筛选在 Header 下；指标、图表、列表按 12 列栅格排布；列表卡片自行分页或展示“查看全部”。 | 页面主内容滚动；每个卡片仅在自身列表/日志溢出时内部滚动。 | 模式：监控、分析、概览。卡片允许局部 Loading / Error / Empty，不因单卡失败清空整个看板。 |
| 分步流程页 `.ds-page--workflow` | 左侧流程名称和当前步骤；右侧只放保存草稿等辅助操作。 | 步骤导航在内容顶部或左侧；当前步骤内容独占 Content；无分页。 | 当前步骤内容滚动；上一步、下一步、提交固定在底部。 | 模式：导入、向导、发布。切换步骤前校验当前步骤；已完成步骤可回看，未完成步骤不可跳过（除非业务明确允许）。 |
| 工作台 `.ds-page--workbench` | 顶部展示当前任务、全局状态和任务级操作。 | 左侧资源/队列，中间主任务区，右侧检查器或上下文信息；无通用分页。 | 三栏均可独立滚动；中心主任务区优先获得宽度。 | 模式：持续操作、任务处理。局部刷新只更新对应栏；断网或权限变化以栏级提示呈现，不遮挡其他可用区域。 |
| 全屏编辑器 `.ds-page--editor` | 顶部任务栏包含标题、保存状态和少量关键操作。 | 左侧资源，中间画布，右侧属性；画布工具栏在画布内容内，不作为页面级浮层；无分页。 | 画布、资源、属性三栏各自滚动或缩放；仅画布可占满剩余空间。 | 模式：可视化编辑、建模。保存/发布固定在顶部任务栏；内容 Loading 保留画布框架，错误不遮挡撤销、返回等逃生操作。 |
| 左右分栏页 `.ds-page--split` | Header 说明当前集合或当前对象；主操作归属当前上下文的一侧。 | 左栏为列表、筛选和分页；右栏为详情、预览或编辑；不把两栏内容混为单一表格。 | 左右栏独立滚动；窄屏按“列表 → 详情”纵向堆叠。 | 模式：主从浏览、选择后编辑。右栏未选择时显示引导 Empty；左栏刷新不清空已打开的右栏内容。 |
| 弹窗表单 | Header 左侧为任务标题，Footer 操作遵循 §13.1.1。 | Body 为字段和帮助信息；无页面筛选和分页。 | 结构、尺寸与滚动遵循 §3.2。 | 模式：短创建、短编辑、二次确认。表单校验、Loading 和 Error 在 Body/字段附近显示；未保存保护遵循 §27.17。 |
| 抽屉详情 | Header 左侧为对象名称和状态，右侧为关闭与上下文操作。 | Body 为详情、时间线或辅助配置；按需在 Footer 放提交操作；无分页。 | 浮层关闭见 §16.0，滚动结构见 §3.2。 | 模式：不离开上下文的详情、连续配置。加载中保留 Drawer 壳；对象删除、无权限或接口失败均在 Body 内说明并提供可行去向。 |

当前原型的落地基线：软件产品和装机记录使用列表页模板；产品包/版本管理以及自定义首页方案预览使用左右分栏模板；自定义首页编辑使用全屏编辑器模板。新增页面必须先选择上述模板之一，并在代码评审中注明不适用区域；画布层级例外以 §16.0 的全局规则为准。

### 20.3 可复用业务组合

下列组合位于基础组件之上，页面应优先复用其信息结构和状态规则，不得每页重新发明同一流程。

| 业务组合 | 固定结构 | 关键行为与状态 |
| --- | --- | --- |
| 搜索 + 筛选 + 结果列表 | 搜索框、已生效筛选、结果数、结果区、分页 | 输入防抖不清空现有结果；无结果保留筛选并提供清除筛选；请求失败提供重试。 |
| 批量选择 + 批量操作 | 行选择、已选数、批量操作栏、清除选择 | 仅选中至少一项后显示操作栏；危险批量操作必须确认并显示影响数量。 |
| 创建 / 编辑表单 | 标题、字段分组、字段帮助/错误、固定提交区 | 编辑保留初始值；提交 Loading 防重复；成功后的关闭、停留或跳转由页面明确说明。 |
| 删除二次确认 | 对象名称、影响范围、危险说明、取消/确认 | 确认按钮使用 danger；取消不改变数据；删除成功后回到仍有效的上级列表或上下文。 |
| 状态回退确认 | 对象名称、当前状态、回退后的影响、取消/确认 | 取消发布、停用、终止等会改变线上状态或可编辑性的操作必须二次确认；可恢复的回退使用品牌主按钮，不可逆或有数据损失风险时才使用 Danger；正文说明回退后哪些内容会受影响。 |
| 文件上传 | 选择文件、格式/大小说明、文件列表、逐项状态 | 保留原生可访问文件选择；上传、解析、失败、重试和移除逐项反馈；不因单文件失败丢失其他文件。 |
| 导入与导出 | 导入步骤/校验结果或导出范围/进度 | 导入先校验再确认写入；导出显示生成中、完成或失败，长任务可后台继续。 |
| 设备在线状态 | 状态图标/文字、最后更新时间、必要操作 | 在线、离线、未知均使用文字和图形补充；离线时保留最近数据并标注更新时间。 |
| 任务执行状态 | 任务标识、阶段、进度、开始/结束时间、操作 | 等待、执行、成功、失败、已取消有明确语义；取消高风险或不可逆时确认。 |
| 日志查看 | 日志级别、时间、来源、内容、筛选、定位到底部 | 仅日志面板内部滚动；新日志到达时不强制抢占阅读位置，提供“回到最新”入口。 |
| 参数配置 | 分组、字段帮助、校验、差异/默认值、提交区 | 只读、禁用、错误和已修改状态可区分；未保存离开必须确认。 |
| 长任务进度 | 任务名称、当前阶段、总进度、耗时、后台入口 | 关闭页面后任务可继续时需明确说明；失败说明可恢复动作，完成给出结果入口。 |
| 权限不足 | 权限说明、影响范围、返回或申请权限入口 | 不显示无效重试；保留可访问的页面导航和非受限信息。 |
| 数据加载失败 | 错误标题、简短说明、重试、必要时返回入口 | 有缓存时保留缓存和错误提示；无缓存时替换 Content，不能只留空白。 |

### 20.3.1 配置编排业务模式

字段字典、参数定义、组件创建与构型装配属于同一类“配置编排”任务。它们复用 ProductUI 的 Field、Input、Select、Checkbox、Tag、Button、Modal 与 Drawer，不得在业务页面自行重绘控件。

| 模式 | 承载与固定结构 | 关键规则 |
| --- | --- | --- |
| 编辑参数字段的枚举项 | 短任务使用 Modal；基础字段在上，枚举项编辑区在下，Footer 固定 | 枚举区包含“显示名称 / 标识符 / 操作”列；新增项追加在列表末尾；删除使用无外框 Danger IconButton；标识符去重错误显示在编辑区下方并使用 `role="alert"`。 |
| 创建组件 | 两步 Modal：基础信息与构型 → 模块装配 | 第一步使用两列字段，构型模板和描述占满一行；第二步按槽位顺序展示槽位编号、类型、模块选择器和允许规格。切换步骤保留已填写内容；未完成必填槽位时禁止保存并生成。 |
| 新增 / 编辑级联 | 短任务使用 Modal；父字段取值、关联子字段、关联取值组、Footer | 父字段与子字段按依赖顺序纵向排列；子字段变化立即清理失效的已选值；关联取值组 Header 提供“全选”，Body 内复用 Checkbox 并允许内部滚动。无子字段时展示明确空状态。 |
| 装配模板 | 连续配置使用 Drawer；标题、说明条、逐槽位规则、固定 Footer | 槽位按运动链顺序排列；编号 Tag 与类型名称在左，允许规格在右；未单独选择时继承全局槽位规则。恢复默认只重置当前草稿，不直接写入。 |
| 槽位规则 | 全局配置使用 Drawer；说明条、类型分组、固定 Footer | 每个类型分组由英文类型 Tag、中文名称、全选 Checkbox 和规格项组成；全选状态与子项同步。保存后影响所有构型，必须在说明条中明确作用范围。 |

统一视觉与行为：

- Modal / Drawer 的结构与滚动见 §3.2，关闭、遮罩、焦点和层级见 §16.0。
- 字段控件使用 40px 高度；同一行字段间距 16px，字段组间距 16px，说明条与主要分组间距 16px。窄屏转单列，不压缩文字和热区。
- 选择组 Header 使用弱背景与底部分隔线，Body 使用 Surface；选中由 Checkbox、文字和主题色共同表达，不把整行涂成不可区分的大色块。
- 槽位编号和类型属于元数据 Tag，不承担点击操作；可操作项必须使用 Select、Checkbox 或 Button，不使用 Tag 伪装按钮。
- Footer 主操作数量见 §13.1.1；恢复默认位于左侧，取消与保存位于右侧，恢复默认后仍需用户保存才生效。
- 保存失败保留全部草稿并将字段错误映射回对应位置；跨字段冲突显示表单级摘要，禁止清空已完成的装配或级联选择。

### 20.4 页面级状态矩阵

页面状态必须定义在 Content 或具体模块内；Header、导航和已生效筛选在安全情况下继续保留。图标优先使用系统图标；仅完整 Empty / Error 页面可使用统一插画，不能用装饰插画替代状态说明。

| 状态 | 显示位置与内容 | 操作与去向 | 是否保留原内容 |
| --- | --- | --- | --- |
| 初始状态 | Content 中显示首次进入的说明或可执行的起始操作。 | 提供创建、选择或开始操作；进入对应流程。 | 无既有内容。 |
| 加载中 | Content 使用与最终结构接近的 Skeleton；标题与 Toolbar 保持稳定。 | 默认无操作；超过正常等待时间可按产品规则显示取消或返回。 | 首次加载不保留；刷新不使用此状态清空旧内容。 |
| 局部加载 | 对应卡片、分组、表格区域或按钮内显示进度。 | 仅影响该模块；其他区域仍可操作。 | 保留模块已有内容或固定占位。 |
| 无数据 | 主结果区居中显示“暂无 [对象]”、原因和简短说明。 | 有创建权限时提供创建入口；否则不提供无效按钮。 | 替换结果区，不替换 Header/筛选。 |
| 无搜索结果 | 结果区显示“未找到符合当前条件的结果”。 | 提供清除筛选/搜索入口，回到默认数据集。 | 保留搜索词、筛选条件和 Toolbar。 |
| 网络异常 | Content 或受影响模块显示网络不可用说明。 | 提供重试；若有缓存则可继续查看缓存。 | 有缓存则保留并加提示；无缓存替换受影响区域。 |
| 接口异常 | Content 或受影响模块显示用户可理解的加载失败说明，不展示内部错误对象。 | 可恢复时重试；不可恢复时返回上级或联系支持。 | 同网络异常处理；不清空无关模块。 |
| 无权限 | Content 或受限模块显示权限不足和影响范围。 | 提供返回、切换对象或申请权限入口；不提供重试。 | 保留导航和允许查看的上下文，不展示受限数据。 |
| 内容被删除 | 原详情/编辑 Content 显示“内容已删除”。 | 返回列表、关闭 Drawer/Modal 或选择其他对象。 | 不保留可能已失效的对象内容。 |
| 数据过期 | Content 顶部或受影响模块显示最近更新时间和过期提示。 | 提供刷新；刷新失败转为网络/接口异常。 | 保留过期数据，明确其时间。 |
| 部分加载成功 | 页面顶部或模块顶部显示成功/失败摘要。 | 仅为失败模块提供重试。 | 保留成功模块和已获得数据。 |
| 离线 | Header 或受影响 Content 显示离线状态和最近同步时间。 | 保留只读浏览；需要联网的操作禁用并说明原因。 | 保留可用缓存，不伪造实时状态。 |
| 维护中 | Content 或全局提示区显示维护说明与预计恢复信息（若已提供）。 | 提供返回或稍后重试；不提供会失败的主操作。 | 可安全展示的只读内容可保留，其余替换为维护状态。 |

### 20.5 响应式、溢出与拉伸规则

- 支持的最小视口为 320 CSS px；页面根节点不得设置大于 320px 的 `min-width`。小于 320px 不另行承诺布局，浏览器缩放不视为响应式方案。
- ≥1200px：使用 12 列栅格、24px 页面边距、16px 模块间距；导航为 232px、详情侧栏为 320px。多栏模板保持并列，中心任务区优先伸缩。
- 768–1199px：页面边距 20px、网格/模块间距 12px；导航为 208px、通用侧栏为 272px、详情侧栏为 300px。保留主任务区，次要字段、低频筛选和辅助操作先收纳。
- 320–767px：页面边距 16px、4 列栅格、网格/模块间距 12px；导航和侧栏宽度均为 100%，多栏模板按内容顺序纵向堆叠。列表详情分栏先显示列表，选择后显示详情并保留返回列表入口。
- 表格只能由表格容器横向滚动，页面和 `body` 不得因表格横向滚动；收敛顺序固定为：收紧非核心列 → 隐藏低优先级列 → 固定主标识/操作列 → 表格容器横向滚动。
- 卡片区使用当前 12 列或 4 列栅格。当前容器不足以容纳卡片声明的最小列跨度时，卡片改为独占一行，不得压缩文字、图标和操作热区。
- 页面标题最多两行后截断；对象名、文件名、版本号、编号等不可拆分字段单行省略，并通过详情、Popover 或其他非 Hover 唯一入口查看完整值。说明性长文本允许换行，使用 `overflow-wrap: anywhere` 防止长英文或 URL 撑破容器。
- Toolbar 空间不足时保留一个页面级主操作；次要操作收纳至 More，搜索与复杂筛选可进入 Drawer。按钮不得通过缩小到未发布尺寸或折行挤压来适配。
- Modal / Drawer 的最大尺寸与唯一滚动区统一遵循 §3.2，本节只定义页面响应式关系。
- 可拉伸的看板卡片、图表、日志、3D 或编辑器区域不得整体等比缩放。紧凑态先隐藏次级信息和收纳低频操作，标准态展示完整核心内容，展开态增加明细、趋势或可见行数；每个业务组件必须声明三态触发区间、可隐藏字段和唯一内部滚动容器。

## 21. 动效规范

动效只用于表达状态变化、空间关系和操作结果，不用于装饰或延迟用户操作。业务页面只能使用以下已发布 Token，不能自行声明时长、缓动曲线或全局关键帧。

| Token | 已发布值 | 用途 |
| --- | --- | --- |
| `--ds-motion-duration-fast` | 120ms | Focus、Pressed、输入框/菜单项 Hover 等微反馈。 |
| `--ds-motion-duration-mid` | 160ms | Hover 颜色、状态切换、下拉菜单、列表项增删、页面内容切换。 |
| `--ds-motion-duration-slow` | 240ms | Modal、Drawer 等空间关系明确的进入动效。 |
| `--ds-motion-duration-loading` | 800ms | Loading 指示器完整旋转一周。 |
| `--ds-motion-ease-in` | `cubic-bezier(0.4, 0, 1, 1)` | 退出、收起。 |
| `--ds-motion-ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 进入、展开。 |
| `--ds-motion-ease-in-out` | `cubic-bezier(0.2, 0, 0, 1)` | 颜色、边框、阴影、尺寸不变的状态切换。 |

保留既有 `--ds-duration-*` 与 `--ds-ease-*` 仅用于兼容存量代码；新页面和新适配代码使用 `--ds-motion-*`。

### 21.1 动效场景矩阵

| 场景 | 允许的动效 | 时长与缓动 | 禁止项 |
| --- | --- | --- | --- |
| Hover 颜色过渡 | 背景、边框、文字、阴影颜色变化；不得改变占位尺寸。 | `mid` + `ease-in-out`；极轻量输入反馈可用 `fast`。 | 位移、弹跳、缩放和延迟触发。 |
| Modal 进入 / 退出 | 遮罩淡入/淡出；内容进入可淡入并从 0.96 缩放至 1，退出反向。 | 进入 `slow` + `ease-out`；退出 `mid` + `ease-in`。 | 从屏幕边缘滑入、长于 `slow`、关闭后继续阻塞操作。 |
| Drawer 滑入 / 退出 | 遮罩淡入/淡出；面板沿其打开方向滑入、反向退出。 | 进入 `slow` + `ease-out`；退出 `mid` + `ease-in`。 | 整页跟随缩放、跨方向滑动、在内容未关闭时提前移除焦点限制。 |
| Dropdown / Popover / Select 展开 | 淡入，最多从 `scale(0.96)` 与 `translateY(-2px)` 恢复到原位。 | 进入 `mid` + `ease-out`；退出 `fast` + `ease-in`。 | 超过 2px 的位移、弹簧/弹跳、因动效改变浮层最终定位。 |
| Loading 旋转 | Spinner 匀速旋转；Skeleton 只允许低对比度、尺寸固定的提示。 | `loading` + `linear` 无限循环。 | 用旋转替代错误说明；因 Loading 改变按钮、卡片或表格尺寸。 |
| 页面切换 | 仅 Content 可淡入/淡出；Header、导航、已生效筛选保持稳定。 | `mid` + `ease-in-out`。 | 整页横向滑动、全局路由转场、清空原内容后再闪现新内容。 |
| 列表增删 | 新项淡入并最多上移 2px；删除项淡出后再移除。排序/筛选变化直接更新结果。 | `mid` + `ease-out`（新增），`fast` + `ease-in`（删除）。 | 动画 `height`、连续重排、对长列表逐项播放。 |
| 状态切换 | 颜色、图标、文字和 Focus Ring 同步切换；成功、错误、离线等必须保留可读文案。 | `mid` + `ease-in-out`。 | 仅靠闪烁或颜色表达状态；用动效掩盖失败或加载超时。 |

### 21.2 实现与无障碍约束

- 仅可动画 `opacity`、`transform`、颜色、边框色和阴影；禁止通过动画 `width`、`height`、`margin`、`padding` 改变布局，也不允许因动效造成内容跳动。
- 进入动效不得阻塞点击、键盘 Focus、Esc 关闭或异步请求；退出动效结束后才卸载浮层，焦点恢复规则不因动效改变。
- 同一元素同一时刻只承担一种主视觉动效。Loading、Error、Success 等业务状态优先级高于装饰动效。
- `prefers-reduced-motion: reduce` 下禁用非必要的位移、缩放、旋转和列表增删动效；Hover/Focus/状态变化立即完成，Spinner 静止但保留 Loading 文案或图形。
- 动效验收应覆盖 Light/Dark、键盘操作、触控操作、Loading、Error、Success、页面切换和减少动效偏好；任何状态不得仅通过动效传达。

## 22. 风格预设

风格预设位于主题之上：Theme 决定明暗模式，Style Preset 决定色彩倾向、形状、密度与层级表现。默认使用 `current`；任何新增预设都必须通过独立作用域启用，禁止覆盖 `current` 的 Token 或组件契约。

### 22.1 Current

- 状态：Stable。
- 支持主题：Light / Dark。
- 使用 `theme.light`、`theme.dark` 与 `shared` 中发布的默认 Token。
- 未显式设置风格时必须回退到 Current，保证存量页面与既有视觉不变。

### 22.2 Industrial

- 状态：Experimental；支持 Light / Dark。
- 适用于设备监控、机器人配置、运行状态、日志与高密度数据操作。
- Light 页面底色统一使用中性灰 `#F0F0F0`，内容容器使用纯白，文字与边框继续采用工业蓝灰层级；Dark 使用深海军蓝黑背景和蓝灰容器。钢铁蓝或品牌紫承担主按钮、选中、Focus Ring、Key 边框与导航状态；工业橙只用于设备模型、关键运行信号和极少量强调，禁止作为页面通用主色或大面积铺底。绿色只表达成功/在线，黄色只表达警告，红色只表达危险或错误。
- B 端组件层级：Primary 使用实色钢铁蓝；Default 使用白色/深色 Surface 与清晰描边；Secondary 使用浅品牌底并保留品牌色边框；Danger 使用错误浅底与错误色边框。Input、Select 默认必须具有可见边框，Table Header 使用轻品牌色表头，Selected 与 Hover 必须可区分。
- 圆角：按钮、输入和选择器 4px；卡片、弹窗和浮层 6px；状态 Tag 可保留胶囊圆角。
- 层级：普通卡片不使用阴影，通过背景与边框分层；浮层和对话框仅使用低扩散阴影。
- 描边：Light 普通边框使用低对比浅灰蓝，结构分隔线仅比普通边框深一级；Dark 边框应贴近容器底色，禁止用高亮描边切割整个页面。Focus、Selected、Error 等状态边框不受此弱化规则影响。
- 首页左右工作区只允许一条低对比分隔线；选中方案卡片使用浅强调底加 1px 混合强调边框，禁止使用 2px 深色描边。普通删除操作使用危险浅底、危险文字和轻危险描边，Hover / Pressed 逐级增强；二次确认弹窗中的最终删除按钮使用危险实色。
- 密度：Industrial 的应用外壳采用无缝框架，页面外边距与外壳模块间距为 0；表格、表单、配置卡片和组件工作区属于内容层，必须恢复 12px 栅格间距，表头 40px、数据行 48px。Current 仍使用默认页面边距与模块间距。不得缩小文字、键盘焦点或触控热区换取密度。
- 首页预览和固定导航分栏可以通过单条 1px `borderStrong` 分割线直接连接；列表表格保留 16px 水平安全边距和独立单边框，表单及配置卡片保留 12px 间距与 6px 圆角。相邻内容卡片禁止各自带边框后再零间距贴合，避免双线。页面标题栏、工具栏、表格单元格和卡片内容仍保留 12–16px 内边距。
- 动效沿用共享 Motion Token，不增加霓虹呼吸、扫描线动画、闪烁告警或持续发光。
- Focus Ring 使用钢灰蓝交互色并保持可见；设备信号不得只通过橙色表达，必须保留文字、图标或结构提示。

### 22.3 切换与实现

- 风格选择使用 `data-style="current|industrial"`、主题选择使用 `data-theme="light|dark"`、工业主题色使用 `data-industrial-color-theme="steel|cobalt|graphite"`；三者必须是独立状态。
- Industrial 与 Current 共用 Light / Dark 主题状态；切换 Style 不改变 Theme，切换 Theme 也不改变 Style。退出 Industrial 后恢复同主题的 Current，不能残留工业色值、圆角或阴影。
- Industrial 默认使用 `steel`。颜色选择器仅在 Industrial 启用后显示；Current 不读取、不渲染工业主题色覆盖。
- `steel`：默认钢铁蓝界面＋橙色设备信号；`cobalt`：沿用相同的中性灰白工业界面，只在主操作、选中与焦点状态使用品牌紫（Light 主色固定为 `#241F7D`），并保留橙色设备信号；`graphite`：石墨灰界面＋琥珀橙设备信号。
- 三套工业主题色只能覆盖颜色与信号 Token，共享 Industrial 的小圆角、紧凑密度、动效、组件 API 和状态规则，禁止复制三套组件。
- 组件继续使用相同 Button、Input、Select、Table、Tabs、Menu 契约；预设只能替换已发布 Token，不能复制另一套组件实现。
- 用户选择可持久化，但首次访问、存储无效或预设加载失败时必须回退 Current。
- 自动化验收至少覆盖：默认不启用 Industrial、Current 前后截图一致、三套工业主题色的 Light / Dark、切换往返无 Token 残留、键盘焦点可见、正文和状态对比度合格。

## 23. 数字造机产品一致性规范

所有数字造机及其同级业务系统默认使用 Current 风格，并复用统一产品外壳与管理页面 Recipe。业务语义可以变化，但导航、顶栏、页面模板、组件来源和 CRUD 承载方式不得自行重新设计。

### 23.1 产品外壳

- 产品级导航、全局顶栏、滚动关系及响应式行为以 `docs/product-shell.md` 为准。
- Current 桌面导航宽 200px、顶栏高 52px、一级导航项高 48px；业务页面不得覆盖这些尺寸。
- 产品外壳只使用语义 Token，不增加工业场景背景、装饰性仪表、渐变或纹理。

### 23.2 页面与 CRUD

- 列表、新增/编辑、详情、导入和连续配置按 `docs/page-recipes.md` 选择承载方式。
- 短创建和短编辑使用 Modal；不离开列表上下文的详情使用 Drawer；长表单和多步骤任务使用独立页面或 Workflow。
- Current 表格表头 44px、数据行 60px、单元格水平内边距 16px；操作列基准宽 96px并使用小尺寸 IconButton 操作组。
- **Industrial 预设密度**：表头 40px、数据行 48px（单元格内边距不变）；仅在明确启用 Industrial 样式预设时生效，不得与 Current 预设混用于同一张表格。
- 操作列的宽度、收敛和无障碍统一见 §15.1。
- 页面主操作数量遵循 §13.1.1；行内查看、编辑、删除不与页面主操作混用。

### 23.3 实现边界

- 当前工程业务组件通过 `docs/product-ui-mapping.md` 映射到正式 `Product*` 组件。
- 已有 ProductUI 能力不得使用原生控件、底层组件库或页面私有 CSS 重复实现。
- ProductUI 尚未覆盖的能力必须先补组件契约、Token、正式导出与验收项，再进入业务页面。
- 规范验收同时检查发布包内部一致性和运行时映射；仅文档章节或 JSON 可解析不代表实现符合规范。

## 24. 无障碍与高对比度

- 发布目标为 WCAG 2.2 AA：常规文字与背景对比度至少 4.5:1，大字至少 3:1；控件边界、状态图形和 Focus 指示至少 3:1。自动校验覆盖主按钮文字、表头和 Info/Success/Warning/Danger 状态文字。
- 页面在 200% 浏览器缩放下不得丢失内容或操作，在 400% 下允许按移动布局重排；除二维画布、宽表和 3D 视口外，不得出现双向滚动。
- 所有核心流程必须可仅用键盘完成。焦点顺序与视觉顺序一致；Modal/Drawer 限制焦点并在关闭后返回触发元素；Menu、Tree、Tabs、Select、DateTimePicker 和 Table 采用各自的复合控件键盘模式。
- 图标按钮必须有可访问名称；装饰图标对读屏隐藏。状态更新使用合适的 `aria-live`：普通加载和结果数量用 `polite`，阻断性错误用 `assertive` 或 `role="alert"`，不得重复播报同一消息。
- `forced-colors: active` 下保留系统边框、选中、勾选、错误和焦点指示；不得把 `outline` 移除后不提供替代。颜色之外必须有文字、图标、形状或位置提示。
- 触控热区至少 44×44 CSS px，鼠标高频图标操作热区至少 32×32px；视觉图标可以更小。Hover 不承载唯一内容或唯一操作。
- 动效遵循 `prefers-reduced-motion`；自动轮播、实时刷新和 3D 镜头运动必须可暂停。超时任务应支持延长或避免使用固定超时。

## 25. 3D 与图表规范

### 25.1 3D Scene Scope

- 3D 视口使用独立 `components.scene3d` Token。Industrial Light/Dark 均使用近黑 Scene 背景，页面主题不得把画布反相为浅色；页面 Surface、表单和浮层仍使用正常主题 Token。
- 默认、Hover、Selected、Disabled、Loading、Error、离线和数据过期均需有场景内反馈及场景外文字说明。Selected 轮廓必须高于 Hover；不可只通过材质颜色表达对象状态。
- XYZ 坐标轴颜色固定映射且同时显示轴字母；网格线分主次层级，HUD、测量、坐标和单位使用高对比场景文字。模型、网格和标签不得直接硬编码色值。
- 首次加载保留视口尺寸并显示进度；模型解析失败提供错误原因与重试/替换入口；WebGL 不可用时显示 ContentState，不留空白画布。
- 平移、旋转、缩放、框选和复位提供鼠标/触控说明及键盘替代；高风险编辑需有撤销。镜头自动运动可暂停，减少动效模式下禁用非必要飞行动画。

### 25.2 图表

- 类别色使用 `components.chart.categorical` 发布序列，并经过常见色觉缺陷检查；同一业务维度在同一产品中保持颜色稳定。状态色只表示状态，不作为普通数据系列轮换色。
- 坐标轴、网格、标题、图例、Tooltip、阈值和选中状态均引用图表 Token。正文、标签和数值满足对比度；细线、点和面积不得只依赖颜色区分，应辅以形状、线型、标记或直接标签。
- 图表必须有文本标题、数据口径、时间范围、单位和最近更新时间；加载、无数据、筛选无结果、部分数据、过期和请求失败使用 ContentState，不伪造为零值。
- Tooltip 支持键盘/触控访问并限制在视口内；图例可聚焦和切换时需声明状态。关键数据提供表格或可访问摘要，不能要求读屏用户理解 Canvas/SVG 几何。
- 容器变化时重排标签、图例和可见数据量，不整体缩放字号与点击热区。高密度数据采用抽样、聚合或视窗裁剪，并明确其数据口径。

## 26. 多语言与本地化规范

本章节约束产品界面文案、组件布局、数据格式和交互在不同语言环境下的表现。多语言不是逐字翻译；页面必须在切换语言后仍保持信息完整、操作可用、格式正确和无障碍语义一致。

### 26.1 支持范围与语言声明

- 每个发布版本必须在产品配置和发布说明中声明 `supportedLocales`、默认语言和回退语言。Locale 使用 BCP 47 标识，例如 `zh-CN`、`en-US`；禁止使用 `cn`、`english` 等私有缩写。
- 当前最低设计与视觉验收基线为 `zh-CN` 和 `en-US`。这表示组件必须能承载中英文，不代表未经实现和测试的语言已经对用户开放。
- 回退顺序固定为“用户选择 → 浏览器或账户语言 → 产品默认语言 → 消息 Key”。生产环境不得显示空白、`undefined` 或未处理的插值占位符；开发与测试环境应显式暴露缺失 Key。
- 用户选择的语言需要持久化，并在刷新、重新登录和同一产品内跳转后保持。切换语言不得同时改变主题、工业风预设、筛选条件或业务数据。
- 第三方组件、日期选择器、校验器、图表和编辑器必须接收同一个 Locale Context；禁止局部组件自行读取浏览器语言，造成同页多种语言和格式。

### 26.2 文案资源与消息模板

- 文案 Key 使用稳定的业务语义，例如 `model.create.success`，不得以中文原文作为 Key，也不得把 DOM 路径、页面位置或颜色写进 Key。
- 完整句子由 ICU MessageFormat 或等价消息模板管理。禁止通过 `title + count + unit`、字符串相加或在翻译结果外追加标点来组成句子。
- 复数、序数、性别、语序和选择分支必须由消息模板处理；不得假设所有语言都使用中文语序或只有单复数两种形式。
- 插值变量必须命名明确并保持类型稳定，例如 `{modelName}`、`{count, plural, ...}`。用户输入默认作为纯文本转义，禁止翻译资源或插值注入 HTML。
- 链接、加粗等富文本使用受控组件占位，不在翻译字符串中保存任意 HTML。译文不得改变权限、危险等级、业务状态或按钮行为。
- 产品名、商标、代码、文件名、版本号、设备编号、协议名和未经批准的业务缩写默认不翻译；是否翻译必须进入术语表。
- 短 Toast、Tag、按钮和状态文案末尾不加句号；说明段落是否使用标点由对应语言的完整消息决定，标点不得在组件代码中额外拼接。

#### 26.2.1 标准版与简短版

同一业务含义按展示位置使用两档文案，不得用同一长文案挤压所有位置：

- 标准版用于页面标题、模块名称、表单字段、弹窗标题、说明文案等需要完整表达业务含义的场景。
- 简短版用于导航、Tab、Tag、按钮、卡片入口、表格表头等空间有限且上下文明确的场景。
- 允许缩短冗余词：父级已经表达“管理”时，子级可去掉 Management；例如导航一级为“数据管理”时，二级可只写“字典”。
- 全局操作词全系统统一：新增 / Create、添加 / Add、编辑 / Edit、删除 / Delete、移除 / Remove、保存 / Save、刷新 / Refresh、搜索 / Search、重置 / Reset、导入 / Import、导出 / Export 等；不得在同一产品的不同页面使用同义不同词的操作文案。

### 26.3 文案长度与布局适配

- 设计和开发至少按英文相对中文增长 30% 验收；全局导航、按钮组、Tabs、表头、Tag、筛选器和 Modal Footer 必须使用伪本地化长文案再检查一次。
- 控件以 `min-width`、内容自适应和容器重排为主，不通过减小字号、压缩字符间距或覆盖翻译来解决空间不足。
- 页面主操作、确认、取消、删除等关键按钮不得截断。空间不足时先增加按钮宽度、换行排列或收纳次要操作；不得只显示不明确的省略号。
- Tab 和 Segmented 文案保持单行；空间不足时使用横向滚动或 More。Tag 可随内容扩展，但不得无限撑开表格列；过长状态应使用短状态词并在邻近位置提供说明。
- 表单 Label 默认允许换行，桌面端最多两行；字段栅格需要按最长目标语言重新评估。错误、帮助和计数信息在控件下方自然增高，不使用固定高度遮挡下一字段。
- 表头可按列规则换行或省略；关键字段必须通过详情、Popover 或可访问名称提供完整值。操作列固定宽度时，图标按钮需要本地化 Tooltip 和 `aria-label`。
- Modal、Drawer、Toast、Notification 使用最小高度而非固定高度；内容增长、唯一滚动区与防双滚动规则统一见 §3.2。
- 长英文、URL 和不可预测标识使用 `overflow-wrap: anywhere`；数字与单位、日期与时区、正负号与数值、状态图标与状态文字不得断行分离。

### 26.4 日期、时间、数字与单位

- 日期、时间、数字、百分比、货币、列表和相对时间统一使用 `Intl.DateTimeFormat`、`Intl.NumberFormat`、`Intl.ListFormat`、`Intl.RelativeTimeFormat` 或项目批准的等价格式化层，禁止手工拼接千分位、货币符号、年月日和上午/下午。
- 后端保存明确的瞬时值；界面格式化时显式传入 IANA 时区。设备时区、站点时区与用户时区同时存在时，必须在字段、列头、Tooltip 或页面说明中标明当前口径。
- 日期范围不得只依赖短数字格式造成月/日歧义。跨日、跨年和夏令时区间需要显示足够上下文；导出文件必须声明使用的 Locale 与时区。
- 数字输入允许用户按当前 Locale 输入小数和分组符号，但提交前转换为稳定的数据值；显示值与存储值分离。编号、版本号、IP、坐标、校验码等标识符不得按普通数字添加千分位或本地数字替换。
- 单位名称和摆放顺序通过格式化消息处理；不得把单位硬编码在 Input 内外两处。单位换算属于业务规则，不能仅因切换语言自动改变数值含义。
- 表格数值继续使用等宽数字并按数据类型对齐；排序和筛选基于原始值，不基于格式化后的显示字符串。

### 26.5 搜索、筛选与排序

- 搜索需按 Locale 处理大小写、全半角、变音符号和常见空白差异；业务同义词、中文名、英文名和稳定标识符由可维护的别名表提供，不依赖机器翻译即时生成。
- 中文、日文、韩文输入法处于 composition 阶段时不得提交搜索、触发最终校验或清空结果；`compositionend` 后再执行防抖查询。
- 文本排序使用显式 Locale 的 `Intl.Collator` 或等价实现；数字版本、编号和文件名按业务排序规则处理，不能直接按格式化字符串或 Unicode 码点排序。
- 筛选选项的显示文案可翻译，提交值必须保持稳定。切换语言后保留已选筛选值、分页和查询条件，并重新渲染对应语言的 Label。
- 无结果、加载失败和结果数量使用完整国际化消息；不得拼接“共”+ 数字 +“条”，也不得把后端英文错误原样展示给用户。

### 26.6 组件与交互要求

| 组件 | 多语言要求 |
| --- | --- |
| Button / IconButton | Button 关键动作不截断；IconButton 的 Tooltip、`aria-label` 和确认文案同步翻译。 |
| Input / Select / DateTimePicker | Label、Placeholder、Help、Error、空选项与月份/星期来自同一 Locale；值与显示文案分离。 |
| Tabs / Menu / Breadcrumb / Steps | 文案增长后滚动、收纳或换行策略明确；当前位置、步骤状态和折叠项仍可被读屏识别。 |
| Table / Pagination | 表头、空态、排序说明、选择数量、每页数量和总数完整本地化；排序基于原始值。 |
| Tag / Status | 使用统一术语表和语义色；状态短词不加句号，不通过缩小字号容纳译文。 |
| Modal / Drawer | 标题、描述、字段和 Footer 操作同时验收长文案；危险确认不得因翻译被截断或降级。 |
| Toast / Notification | 最小高度可扩展；标题、说明、关闭与重试均本地化，短说明末尾不额外拼接句号。 |
| Tree / 3D / Chart | 节点、轴、图例、Tooltip、单位和可访问摘要本地化；对象 ID、坐标轴 X/Y/Z 等稳定标识按术语表处理。 |

### 26.7 RTL 与双向文本

- 当前若未正式支持 RTL，必须在 `supportedLocales` 和发布说明中明确；不得只镜像部分页面形成“半 RTL”界面。
- 承诺 RTL 后，根节点同步设置正确的 `lang` 与 `dir`，CSS 优先使用 `margin-inline`、`padding-inline`、`inset-inline`、`border-inline` 等逻辑属性。
- 导航、面包屑、步骤方向、抽屉进入方向、分页、展开箭头和前进/后退图标按阅读方向镜像；播放、下载、关闭、设备物理方向、3D 坐标轴等不具有阅读方向的图标不得盲目镜像。
- 混合显示英文 ID、版本号、IP、坐标和阿拉伯语时，应使用 `<bdi>`、`dir="auto"` 或等价隔离机制，避免标点和编号顺序错乱。
- 表格数值对齐和操作列位置需要按产品定义验收，不可简单把整张表 `transform: scaleX(-1)`。

### 26.8 无障碍与运行时行为

- `html[lang]` 必须随语言切换更新；RTL Locale 同步更新 `dir`。页面标题、Landmark、表单错误、Toast 和动态结果数量均使用当前语言。
- 可访问名称与可见文案语义一致。不得只翻译视觉文字而遗留英文 `aria-label`，也不得把 Tooltip 作为 IconButton 唯一可访问名称。
- 语言切换完成后用 `aria-live="polite"` 简短通知，不强制刷新页面；焦点保持在语言选择器或返回合理位置，Modal/Drawer 打开期间切换语言不得丢失未提交内容。
- 语言资源按 Locale 分包加载时必须有缓存、超时和回退；加载期间不清空当前页面或闪烁显示 Key。资源失败需要保留上一次可用语言并给出可理解反馈。
- 日志、埋点和接口参数使用稳定 Key/枚举值，不把翻译后的展示文案作为业务判断、权限判断或分析维度。

### 26.9 交付与验收清单

- [ ] 发布清单声明支持语言、默认语言、回退语言、时区口径与 RTL 状态。
- [ ] `zh-CN`、`en-US`、30%–40% 膨胀伪语言和至少一个非 UTC 时区通过核心页面验收。
- [ ] 语言切换保留主题、风格、路由、筛选、分页、表单草稿和当前业务上下文。
- [ ] 页面无硬编码可见文案、字符串拼接句子、缺失 Key、未替换占位符和混合语言组件。
- [ ] Button、Tab、Tag、表头、表单错误、Modal/Footer、Toast/Notification 不截断关键文案或发生重叠。
- [ ] 日期、数字、货币、单位、复数、列表、排序和搜索使用统一 Locale 层。
- [ ] IME 输入、键盘操作、读屏名称、动态播报和 200%/400% 缩放通过验收。
- [ ] 若支持 RTL，增加完整 RTL 截图和交互矩阵；若不支持，在发布说明中明确。
- [ ] 翻译资源经过产品术语表、设计走查和本地化审校，不以机器翻译结果直接上线。

## 27. 交互规范

本章是页面、业务组件与基础控件的统一行为契约。设计稿必须标明关键状态和转移，开发必须使用语义化控件并保持鼠标、触控、键盘和读屏行为一致。只有会影响结果的业务差异才可以覆盖默认行为，并必须在组件契约中明示。

### 27.0 交互领域、规则求值与冲突处理

**领域归属**：鼠标、触控、键盘、语音或辅助技术都属于“输入方式”。它们共享命令语义和权限判断，但不共享事件模型、热区或手势，因此鼠标与触控保留独立章节；键盘导航、单个快捷键绑定、快捷键配置与冲突管理统一归入“键盘与快捷键”，不设置“快捷键”和“快捷键体系”两个同级入口。

**规则最小模型**：任何可配置交互规则至少声明 `id / scope / trigger / preconditions / effect / priority / exclusiveGroup / fallback`。单个快捷键只是 `trigger` 的一种；快捷键体系负责注册、作用域、平台映射、冲突检测和帮助展示，两者是实例与管理机制的关系，不是并列概念。

**求值顺序**：一次触发先过滤不适用规则，再按以下顺序裁决；高层规则可阻止低层规则，但不得静默改写其数据。

1. 安全、权限、资源锁与不可逆风险；
2. 未保存内容、数据完整性与并发冲突保护；
3. 当前模态层、焦点所有权与输入法 composition 状态；
4. 当前组件或编辑器的局部作用域规则；
5. 用户明确配置且已通过冲突校验的规则；
6. 页面、产品与平台默认规则；
7. 无规则命中时执行已声明的安全 `fallback`，否则不产生副作用并提供可诊断记录。

**互斥与并行**：同一 `trigger + scope + preconditions` 下，若两个规则产生互斥结果，必须通过不同 `priority` 或同一 `exclusiveGroup` 明确唯一胜者；同优先级且结果冲突属于配置错误，禁止发布。只有 effect 相互独立、可交换且重试幂等时才允许并行生效；写操作默认串行。

**循环依赖**：规则依赖关系必须构成有向无环图。发布与保存前执行环检测；发现 A → B → A、优先级闭环或“开启 B / 关闭 A”的相反效果链时，拒绝保存并展示完整依赖路径，不允许按注册顺序、加载顺序或最后写入偶然决胜。

**动态冲突**：运行时条件变化导致原胜者失效时，重新执行完整求值，不直接启用下一条旧结果；已产生副作用的规则必须先完成、取消或回滚。每次裁决应保留命中规则、被抑制规则、最终 effect 和原因，供测试与问题排查。

### 27.1 状态模型

- 交互元素基础状态统一为 `Default / Hover / Focus / Pressed / Selected / Disabled / Loading / Error`；业务状态与交互状态分开存储和表达。
- Hover 只表示当前可交互；Focus 表示键盘焦点；Pressed 只在指针或按键按下期间存在；Selected 是持续的当前选择，四者不得混用。
- 状态可组合时保留双方语义，例如 `Selected + Hover`、`Error + Focus`、`Checked + Disabled`；不得因 Hover 覆盖 Selected，或因 Focus 隐藏 Error。
- Loading 禁止重复触发同一操作，但不等同于无原因的 Disabled；需保留操作名称、尺寸与进度语义。
- 状态变化同时更新文案、图标、ARIA 属性和可用操作；不得仅更换颜色。
- 设计与验收至少覆盖默认、主要组合状态、异常状态和状态恢复路径。

### 27.2 鼠标与触控

- 鼠标可见操作热区至少 32×32px；触控热区至少 44×44px，相邻独立触控目标间距至少 8px。
- 单击执行主操作；双击只用于桌面端高频且已被用户熟知的行为，并必须同时提供单击或菜单替代。
- 右键菜单不得成为功能的唯一入口；等价操作需在可见菜单或 More 中提供。
- Hover 不得承载唯一信息或唯一操作。触屏上使用点击、聚焦、长按辅助或显式说明提供等价能力。
- `pointerdown` 只呈现 Pressed，在 `click` / `pointerup` 且指针仍位于有效热区时才执行；滑出热区后释放应取消。
- 缩放、拖动、横向滑动等手势不得阻断系统级滚动与辅助功能；业务手势必须有可发现的控件替代。

### 27.3 键盘与快捷键

- `Tab` / `Shift+Tab` 按视觉阅读顺序在可操作元素间移动；隐藏、Disabled 和装饰元素不进入 Tab 序列。
- Button 使用 `Enter` 或 `Space`；Link 使用 `Enter`；Checkbox 和 Switch 使用 `Space`；不得用不可聚焦的 `div` 模拟。
- Radio、Tabs、Menu、Tree 等组合控件在组内使用方向键，只保留一个 Tab 停靠点；`Home` / `End` 移到首尾项。
- `Esc` 关闭当前最上层可关闭浮层或取消当前模式，不可连锁关闭多层；有未保存数据时先进入确认流程。
- 列表、表格和树在需要组内导航时使用 roving tabindex 或 `aria-activedescendant`，不得让每个单元格无条件进入 Tab 序列。
- 快捷键只用于高频、可恢复或有明确确认的操作；不可逆危险操作不得由单一快捷键直接执行。所有快捷键必须有可点击的等价入口。
- 全局与局部快捷键按上下文分层：页面级高频命令使用全局作用域，列表、画布和编辑区使用局部作用域；同一按键同时命中时按第 27.0 节求值，局部规则仅在焦点确实位于其作用域内时优先。
- Mac 使用 `Cmd`，Windows / Linux 使用 `Ctrl`；界面按当前平台显示键位，帮助面板可并列展示映射。输入框、TextArea、富文本和 IME composition 期间保留文本编辑与输入法按键，屏蔽页面级快捷键。
- 快捷键不得拦截操作系统、浏览器或辅助技术的保留组合键；同一上下文不得重复映射。冲突在配置保存前阻止，并说明冲突命令、作用域和建议替代键。
- 快捷键应在菜单、Tooltip 或可搜索的快捷键帮助面板中可发现；帮助面板只展示当前上下文实际可用且已通过权限过滤的命令。
- 带修饰键的组合在按键完成时只触发一次并防止长按重复提交；长按连续执行仅允许用于方向移动等可重复、可撤销的导航操作。

### 27.4 Focus 与焦点管理

- 所有键盘可操作元素必须有清晰的 `:focus-visible` 样式，焦点环与背景对比足够且不被 `overflow` 裁切。
- 页面首次进入时不强制聚焦普通输入框；只在用户意图明确且不会导致触屏键盘突然弹出时自动聚焦。
- Modal 打开后将焦点置于标题、首个可编辑字段或最安全的主要操作，并将焦点限制在弹窗内。
- 关闭 Modal、Drawer、Popover 后将焦点返回原触发元素；若原元素已删除，则返回同级合理元素或容器标题。
- 内容动态刷新不主动抢占焦点；删除、分页、重排后将焦点置于可预期的后继位置并播报结果。
- 视觉顺序、DOM 顺序和键盘顺序必须一致；不得用正的 `tabindex` 数值手工重排。

### 27.5 点击、选择与切换

- 点击是一次原子意图：一个热区只执行一个主行为。行点击、复选框与行内按钮必须隔离事件。
- 当前项、已选项和已展开项分别使用 `aria-current`、`aria-selected` / `aria-checked` 和 `aria-expanded`。
- 单选用 Radio、Select 或单选列表；多选用 Checkbox；独立且立即生效的开关用 Switch；页面或视图切换用 Tabs。
- 至少选中一项时，禁止取消最后一项并说明约束；允许空选时应提供明确的清除方式。
- 批量全选必须写明范围，并以不确定态表示部分选中；筛选条件改变时不可静默改变选择集。
- 切换前后保留合理上下文；若切换会丢失编辑、选择或进度，必须提前告知并允许取消。

### 27.6 搜索

- 当前数据集搜索默认在输入变化后更新，建议防抖 200–300ms；大范围、高成本或精确查询可使用显式提交。
- 输入法处于 composition 期间不触发最终查询；请求可取消或使用序号丢弃过期响应。
- 有关键词时显示清除入口；清除后立即恢复默认结果，焦点保留在搜索框。
- Loading 保留关键词和已有结果；无结果状态展示当前查询并提供清除或修改建议；错误状态提供重试。
- 关键词、筛选、排序、分页属于同一查询状态；搜索词改变默认回到第 1 页，并与 URL 或其他持久状态保持一致。
- 搜索框必须有可访问名称；Placeholder 只是示例，不替代 Label。

### 27.7 筛选与排序

- 已生效条件必须可见，支持逐项清除和一键重置；重置恢复业务默认值，不一定是全部置空。
- 1–2 个高频筛选直接展示，更多条件收入 FilterPanel / Drawer；关闭面板不会丢失已应用条件。
- 默认筛选提交时机遵循 §13.2；只有明确声明为多条件组合的 FilterPanel / Drawer 才使用“应用”，并区分草稿值与已应用值。
- 排序在默认 / 升序 / 降序间循环；当前排序列、方向和多列优先级必须可见且可读屏。
- 排序与筛选基于原始值和稳定枚举，不基于格式化后的展示文字。
- 条件变化后回到第 1 页；若会清除跨页选择，需先明示确认。

### 27.8 表单输入与校验

- 每个字段使用“Label → Control → Help / Error”结构；必填、单位、范围和格式不得只写在 Placeholder 中。
- 校验时机按成本选择：可即时修正的格式在输入或失焦后提示，必填与跨字段规则最迟在提交时校验。
- 错误保留用户输入，在字段附近说明原因和修正方式；提交失败聚焦并滚动至第一个无效字段。
- 异步校验显示校验中，取消过期请求；服务端字段错误映射回对应字段，无法归属的进入表单级摘要。
- 依赖字段变化后清理已无效的子值、候选项和错误，不得提交界面上已隐藏的陈旧值。
- 提交中主按钮进入 Loading 并阻止重复提交；成功后按任务结束状态关闭、重置或保留页面，不得静默清空。
- Readonly 保持正常对比度并允许复制；Disabled 不可编辑或聚焦，且必要时说明原因。

### 27.9 异步操作

本节是 Loading、防重入、过期响应与结果反馈的全局权威契约；组件和页面章节只声明适用状态并引用本节，不再复制完整时序。

- 100ms 内完成的操作无需闪烁 Loading；超过约 300ms 显示局部进度，超过 10s 的任务显示阶段、耗时与后台入口。
- 首次加载使用稳定高度的 Skeleton 或 Loading；局部刷新保留已有数据并标明正在更新，不将整页回退为空白。
- 同一操作必须防重入；可并发请求必须有稳定标识，过期响应不得覆盖新结果。
- 可取消任务提供“取消”并说明已完成部分是否保留；不可取消任务不显示虚假入口。
- 成功反馈说明完成对象和后续结果；失败反馈保留上下文，分为可重试、需修正、需权限和不可恢复。
- 乐观更新只用于可快速回滚的低风险操作；请求失败时恢复原值并告知用户。
- **Skeleton 超时降级**：若数据在 15 秒内未返回，自动降级为 Error 状态并提供重试；不允许无限 Skeleton 掩盖超时或失败。具体超时阈值由页面声明，未声明时使用 15 秒默认值。超时前不向用户显示“等待中”文案，超时后说明加载时间过长及可选重试。

### 27.10 删除与危险操作

- 不可逆或高影响操作必须使用 Danger 语义，与普通操作视觉分离，不将“取消”设为危险按钮。
- 可恢复的状态回退（例如可重新发布、重新启用且不丢失数据）使用品牌主按钮；只有数据永久删除、无法回滚的生产状态翻转或等价不可逆结果才使用 Danger。判断依据是能否无损撤销，而不是“停用”“取消发布”等动作名称。
- 确认层明确写出对象名称、数量、影响范围、是否可恢复和确认动作，避免“是 / 否”等模糊文案。
- 可撤销的单项低风险删除可先执行并提供有时限的 Undo；不可撤销、批量、级联或权限变更必须事前确认。
- 高危操作可要求输入对象名、二次验证或显示影响清单；不以延迟按钮作为唯一防护。
- 删除中阻止重复提交；部分失败时报告成功数、失败数和逐项原因，允许只重试失败项。
- 成功后将焦点移到下一项、上一项或列表标题，并通过可访问状态播报结果。

### 27.11 Dropdown / Popover / Modal / Drawer

- Dropdown 承载短命令或选项；Popover 承载少量说明与轻量操作；Modal 承载独立短任务或高风险确认；Drawer 承载保留当前页面上下文的连续任务。
- 所有浮层使用平台统一 Portal、层级、定位和视口碰撞逻辑；页面不得自建遮罩或任意 `z-index`。
- 触发器同步 `aria-expanded` 与 `aria-controls`；各浮层的关闭条件统一见 §16.0。
- Modal / Drawer 的焦点边界与关闭后返回位置统一见 §16.0。
- Modal / Drawer 的三区结构和唯一滚动区见 §3.2；窄屏转为近全屏，不出现页面与弹层双重滚动。
- 所有关闭入口与焦点返回见 §16.0；未保存修改的离开保护见 §27.17。

#### 编辑容器决策矩阵

| 容器 | 优先使用条件 | 典型编辑 | 不适用情况 |
| --- | --- | --- | --- |
| Inline / Popover | 修改 1–3 个局部属性，立即看到结果，不需长说明或复杂校验 | 重命名、切换状态、设置单个阈值 | 多分区表单、高风险操作、依赖多字段校验 |
| Modal | 任务独立、单步、短表单，用户无需参照背后页面即可完成 | 新建类型、编辑基础信息、确认删除 | 需边看列表 / 详情边编辑，多分区长表单，长时间任务 |
| Drawer | 编辑时需保留并参照当前列表、画布或详情，内容有多分区但仍可一次保存 | 配置规则、编辑详细属性、快速查看并修改对象 | 不需页面上下文的短表单，多步工作流，需要大画布或大量对照 |
| Full page | 多步、长时间、跨分区、需大画布或需可深链接，任务本身是当前主任务 | 创建复杂模型、编排流程、大型配置器 | 仅修改少量属性或一次确认 |

决策顺序：

1. 编辑时是否需持续参照当前页？需要时优先 Drawer，不需要时继续判断 Modal 或整页。
2. 任务是否为单步、短时、可一次提交？是时优先 Modal；多步或长时任务优先整页。
3. 是否需要大画布、复杂对照、深链接或频繁切换子任务？任一为是则使用整页。
4. 字段数量只是辅助信号：约 8 个以内的常规字段通常可使用 Modal；超过后需结合分组、字段长度、校验复杂度和上下文需求决定 Drawer 或整页，不得仅按字段数量选型。

硬性边界：

- 不在 Modal 中再打开 Modal；后续任务改为同一 Modal 内切步、替换内容，或升级为整页。
- **多步 Modal 内的步骤切换**：步骤指示器放在 Header 或 Body 顶部（不在 Footer）；向上一步时保留当前步骤已填内容；向下一步时先校验当前步骤，失败时聚焦第一个无效字段并阻止跳转；步骤指示器使用已发布 Steps 契约，不自行设计进度 UI。
- 不为了容纳长表单而无限加高 Modal；溢出处理遵循 §3.2，长时多分区任务应改用 Drawer 或整页。
- Drawer 不等于“更大的 Modal”。若用户不需要看到背后页面，则优先 Modal 或整页。
- 平台统一提供 Modal / Drawer 的宽度、遮罩、Portal、层级、焦点和关闭行为；业务页只选择已发布的尺寸变体，不自建弹层外壳。

### 27.12 Table / List / Tree

- Table 用于按列比较的结构化数据；List 用于以对象为中心的扫读；Tree 只用于真实层级与父子关系，不用缩进伪造树。
- 行选择、行打开、展开和行内操作是独立行为；命中内嵌控件时不触发行级行为。
- 排序、筛选、分页、展开和选择的状态可见、可键盘操作并与请求参数一致。
- 层级组件使用左右键收展、上下键移动；懒加载子节点保留父节点和焦点，失败时在节点附近重试。
- 虚拟滚动必须保留行身份、总数、键盘焦点、选中状态和读屏位置语义；不以 DOM 复用导致读错行。
- 窄屏表格可转为卡片列表或内部横向滚动，但核心字段、排序结果与主操作必须保留。

### 27.13 Loading / Empty / Error / Success

- Loading 表示真实进行中的工作，稳定布局并说明加载范围；不使用无限 Loading 遮掩超时或错误。
- Empty 区分“尚无数据”、“筛选无结果”和“无权查看”；分别提供创建、清除条件或申请权限等真实下一步。
- **无数据且无创建权限**时：空状态提供“为什么为空”的说明 + 可选的“联系管理员”或“申请权限”文字链接（非 Button）；不显示灰色禁用的 Primary 按钮；不提供任何会触发错误的操作入口。
- Error 说明发生了什么、影响范围和用户能做什么；可恢复错误提供重试，输入错误定位字段，系统错误保留追踪标识。
- Success 用于用户无法从界面立即确认的结果；页面已明显变化时不重复弹出冗余 Toast。
- 状态使用标题、说明、图标和语义色中的至少两种线索，不仅依赖颜色。
- 局部状态留在对应容器内；只有整页无法使用时才升级为页面级状态。

### 27.14 滚动与溢出

- 每个页面、Widget 或浮层声明唯一主滚动容器；避免同方向嵌套滚动和触屏上的滚动陷阱。
- 宽表、时间轴和画布在自身容器内横向滚动，不得导致页面级横向滚动。
- Sticky Header / Column 需有不透明背景和边界线索，并不遮挡键盘焦点或锚点目标。
- 文本截断只用于次要或可在其他位置完整查看的内容；核心值通过详情、可聚焦 Tooltip 或复制入口提供完整版本。
- 程序性滚动使用“最近可见”对齐，并尊重 `prefers-reduced-motion`；不得在数据刷新时无原因回到顶部。
- 新消息、日志或实时流仅在用户已位于末尾时自动跟随；用户向上查看时保留位置并提示新内容数量。

### 27.15 拖拽

- 拖拽必须有明确的抓取热区、可拖光标、拖动预览和合法 / 非法放置反馈；不以整行无区分地兼任点击与拖拽。
- 超过移动阈值后才进入拖拽，避免点击抖动被误判；触屏上不得与页面滚动冲突。
- 放置目标在拖动过程中持续可见，自动滚动只在靠近边缘时启动，速度可控且不跳跃。
- 拖拽结果支持撤销，或在高影响场景提供确认；失败时恢复原位并说明原因。
- 必须提供键盘和触控等价方式，例如“移到…”菜单、上移 / 下移按钮或抓取后方向键移动，并播报当前位置。
- Dashboard 中 Widget 坐标、吸附、重排和自动填补由平台负责；Widget 内容不得修改自身或其他 Widget 的外部位置。

### 27.16 上传与文件操作

- 上传入口同时支持文件选择和拖入；明确可接受类型、单个 / 总大小、数量和文件名规则。
- 在上传前校验基本类型和大小，在服务端再校验内容、安全性与权限；不仅依赖扩展名。
- 每个文件显示名称、大小、进度、状态与可用操作；批量上传支持部分成功和只重试失败项。
- 取消未完成上传时说明服务端临时数据是否清理；移除已上传文件按删除风险使用确认或 Undo。
- 重复文件按业务规则提供替换、保留两者或跳过，不静默覆盖；文件名在上传前后保持可追溯。
- 下载、预览和导出在触发后立即反馈；大文件生成使用异步任务，并说明文件名、格式和时区 / 筛选口径。

### 27.17 Undo / Redo 与未保存状态

- Undo / Redo 以用户可理解的原子操作为单位，连续文字输入可合并，独立删除、移动或属性变更不得无关联合并。
- 执行新操作后清除 Redo 分支；跨页、跨会话或协作编辑的历史边界必须明确。
- 撤销后恢复数据、选择和合理焦点，并用可访问状态说明被撤销的操作；无历史时按钮不可用。
- 未保存状态以稳定文案或状态点显示，区分“未保存”、“保存中”、“已保存”和“保存失败”。
- **未保存离开保护统一契约**（各节不再重复，仅引用本条）：表单字段、弹窗内容、行内编辑有任何脏值时，`×` 关闭 / `Esc` / 遮罩点击 / 浏览器后退 / 路由导航 / 关闭浏览器标签均触发保护对话框；对话框提供「保存并离开」 / 「放弃修改」 / 「继续编辑」三个选项（仅关闭弹窗时可简化为「放弃修改」/「继续编辑」）；选“继续编辑”后不修改任何数据；放弃修改后不可恢复且不再提示；自动保存草稿不替代保护——草稿仅在用户主动“放弃”后清除，刷新后恢复草稿需用户确认。
- 自动保存必须有明确状态与失败恢复，不得因断网、冲突或过期响应覆盖更新的本地修改。

### 27.19 动效

- 动效只表达因果、层级、方向和连续性；不为装饰延迟用户操作，不使用大幅弹跳或闪烁。
- Hover 与 Pressed 使用 fast，控件状态过渡使用 mid，浮层和页面空间变化使用 slow；统一使用已发布 Motion Token。
- 进入使用 ease-out，退出使用 ease-in，状态切换使用 ease-in-out；相同模式不得在不同页面使用冲突方向。
- 动画期间交互语义已经生效，不得等到动画结束才更新 ARIA 状态或业务数据。
- 布局动画优先使用 `transform` 和 `opacity`，避免大面积重排；进度指示不得伪装确定性百分比。
- 在 `prefers-reduced-motion: reduce` 下移除非必要移动，保留即时的状态反馈；不以动效作为唯一状态线索。

### 27.20 响应式与触屏

- 响应式根据可用容器而非设备型号决定；组件声明紧凑、标准、展开状态和各自的信息收敛规则。
- 窄屏优先重排，再收纳次要操作，然后隐藏低优先级信息；不对整个界面、字号或按钮等比缩放。
- 触屏可交互目标至少 44×44px，间距至少 8px；视觉图标可小于热区，但焦点环需覆盖实际热区。
- 触屏不依赖 Hover、右键、双击或精细指针；图表和画布的 Hover 详情通过点按锁定、详情面板或数据表提供等价内容。
- 输入框获得焦点时预留虚拟键盘空间，主要操作和当前字段不被遮挡；视口改变不导致双滚动。
- 屏幕旋转、分屏和尺寸切换保留当前任务、输入、选择和滚动上下文，不重置用户进度。

### 27.21 权限、占用与不可用状态

- 无权限不等于系统故障或暂时不可用。界面必须区分“不可见”、“可见但不可操作”、“被其他用户 / 任务占用”和“依赖条件未满足”。
- 涉及敏感信息或不应发现的功能时隐藏入口；用户需理解完整流程时保留可见禁用态并说明原因和获得方式。
- Disabled 控件不可聚焦；需要解释时将 Tooltip / 说明绑定到外层可聚焦容器，不把原因只放在 Disabled 元素上。
- 占用状态显示占用者、开始时间、影响范围和刷新 / 申请接管等有效操作；不伪装为永久 Disabled。
- 操作过程中权限收回、锁过期或版本冲突时保留用户修改，并提供刷新、另存、重新授权或复制内容中的有效路径。
- 前端状态只用于交互提示；服务端必须重新验证权限、锁和资源状态，界面不得将隐藏按钮当作安全控制。

### 27.22 导航、历史状态与列表上下文（权威定义）

- 页面级导航使用真实 URL，确保刷新、深链接、前进 / 后退和新标签页行为一致。
- “返回”默认回到上一个合理业务层级，不盲目等同于浏览器 history.back；外部深链接进入时提供稳定的父级去处。
- **列表上下文完整保留**：从列表页打开详情（无论 Drawer、整页还是弹窗）再返回时，以下状态必须完整恢复：搜索关键词、已生效筛选条件、当前排序、分页页码、多选选择集、滚动位置、已展开的行（如有）。若对象已被删除，对应行移除并将焦点移到相邻行，其余状态不受影响；过期状态以当前数据修正。
- **Tab 状态与 URL 的关系**：
  - Tab 若表示可直达的独立子视图（如不同数据集、可深链接的分页）→ 必须写入 URL 参数，浏览器后退可回到上一个 Tab。
  - Tab 若表示同一视图内的局部切换（如详情 Drawer 内的信息分组）→ 状态保留在内存，各 Tab 的筛选、滚动、未提交输入在当前会话内保留，但不写入浏览器历史——用户点击浏览器后退不会回到上一个 Tab。
  - 同一产品不得混用两种策略；若有疑问，默认使用内存状态且不写入 URL。
- 含未保存修改时，页内导航、面包屑、浏览器后退和关闭容器使用同一离开保护逻辑（见 §27.17）。
- 导航完成后更新页面标题、面包屑、当前导航状态与焦点；单页应用将焦点移到新页面主标题或主内容容器。
- 历史记录只保存用户可理解、可恢复的视图状态；瞬时 Hover、展开动画和临时焦点不写入历史，跨会话恢复范围由业务规则明确。

### 27.23 右键与上下文菜单

- 明确声明哪些元素允许右键：数据行、列表项、树节点、画布对象与空白区域分别提供对应菜单；不允许右键的元素不显示菜单。
- 右键同时选中目标对象（单项右键约定）；在多选上下文中右键不改变已有选择，菜单作用于当前选择；空白处右键提供背景级操作。
- 菜单出现在指针附近且不遮挡目标；靠近视口边缘时自动翻转或平移，保持完整可见。
- 不可用的菜单项显示为 Disabled 并说明原因（无权限、依赖未满足、状态不允许），不直接隐藏。
- Esc、点击菜单外部、滚动或开始新操作时关闭菜单；关闭后焦点回到触发对象。
- 触屏通过长按、对象操作按钮或更多菜单提供等价入口，右键不作为唯一操作方式。

### 27.24 行内编辑 Inline Edit

- 单击或双击进入编辑的行为全站一致；进入编辑时选中现有内容或把光标置于合理位置，并显示编辑焦点样式。
- Enter 保存，Esc 取消并恢复原值；编辑区域提供可发现的保存与取消提示。
- 失焦时保存还是取消由规范统一约定：文本与数值字段默认失焦保存，带显式取消按钮；不确定的字段在失焦前完成校验并保持编辑。
- 校验失败时保持编辑状态、保留用户输入，并在字段附近说明原因与修正方式。
- 切换对象、关闭页面或刷新前存在未保存编辑时，先完成保存或询问处理方式，不静默丢弃修改。
- 行内编辑同样满足键盘路径与可访问名称要求，不使用仅鼠标可操作的编辑入口。

### 27.25 Copy / Paste / Duplicate

- 明确哪些对象可复制或生成副本：列表行、画布组件、参数组、文本片段；不可复制的对象不提供入口。
- 跨页面粘贴仅在剪贴板数据携带完整结构、类型与来源时允许，并声明内容有效期；失效时提示重新复制。
- 复制或 Duplicate 生成新 ID 与创建时间，不继承原对象 ID；引用关系按业务规则重建或断开，并说明结果。
- 粘贴位置按明确规则确定：当前容器内、指针位置或列表末尾；非法目标给出反馈并允许重新选择，不静默丢弃。
- 重复对象自动生成不冲突的名称（“副本 1”“名称 (2)”），并允许立即重命名。
- 剪贴板读取或写入失败时提示原因并提供替代方式（重新复制、导出 / 导入），不得把失败静默当作成功。

### 27.26 多选与范围选择

- Ctrl / Cmd 点击切换单项选择；Shift 点击选择连续范围；框选在列表与画布中使用一致的手势与实时预览。
- 提供全选、清除与 Esc 取消选择；点击空白处清空选择并给出可感知反馈。
- 多选后属性面板显示共有属性；值冲突时显示“多个值”，编辑共有属性应用到全部选中对象。
- 允许混选不同类型对象时只提供通用操作；不允许混选时排除不兼容对象或阻止选择并说明原因。
- 批量操作前展示选中范围与数量，部分失败时报告成功数、失败数与逐项原因。
- 选择状态与数量通过视觉与辅助技术同时传达；触屏通过长按进入多选模式。

### 27.27 Resize / Zoom / Pan

- 可调宽面板提供拖动手柄，宽度限制在最小 / 最大之间；双击分隔条恢复默认宽度。
- 画布缩放以指针位置或视口中心为缩放中心；滚轮行为按平台惯例固定（缩放或滚动），并与修饰键组合保持一致。
- 触控使用双指缩放与双指平移，不与页面滚动冲突。
- 提供 Fit View 与 Reset View：一键适配完整内容或回到默认视图与缩放比例。
- 缩放与平移只改变视图，不改变对象数据与选择；最小 / 最大缩放范围可配置，达到边界即停止。
- 视图状态按页面记忆，返回时恢复合理视图；面板宽度变化不得破坏布局与内容可见性。

### 27.28 自动保存与保存状态

- 保存状态统一为 Modified / Saving / Saved / Save Failed，以状态点持续可见，并通过可访问方式播报变化。
- 保存频率与防抖按任务类型固定：文本输入防抖、结构化修改节流；保存进行中禁止重复触发同一保存。
- 关闭页面或离开前等待进行中的保存完成；保存失败时保留本地修改并提供重试、另存或导出。
- 保存失败原因可读（网络、权限、冲突），失败状态持续到用户处理完成，不因后台重试静默恢复。
- 自动保存不得覆盖用户更新的修改：以最后写入为准合并，过期响应丢弃。
- 显式保存按钮与自动保存语义互补；危险、批量与发布类操作不因自动保存而省略确认步骤。

### 27.29 版本与并发冲突

- 数据被他人修改时提供覆盖、重新加载或合并中的有效选项，并说明各自后果；不以静默覆盖解决冲突。
- 冲突提示展示双方修改摘要与时间并支持查看差异；未解决冲突前阻止保存与发布。
- 版本号在每次成功保存后递增并展示；关键状态支持对比历史版本与回退。
- 编辑锁与只读占用标明占用者、期限与申请接管方式；锁过期前自动续期或提示用户。
- 只读视图中仍可执行复制、导出、收藏等非破坏操作，编辑入口说明不可用原因。
- 冲突或断网期间保留草稿，恢复后引导用户选择解决方式，不丢失任何一方的修改。

### 27.30 实时数据刷新

- 实时刷新采用 Polling 或 WebSocket，并声明刷新频率；界面显示最后更新时间与连接状态。
- 页面不可见时降低频率或暂停刷新，恢复可见后立即刷新并说明数据时间点。
- 新数据不覆盖用户正在编辑或查看的内容；有差异时以“有更新”提示，由用户决定是否应用。
- 刷新失败时保留已加载数据并标注过期时间，提供重试入口；不伪装为最新。
- 高优先级变化（告警、状态翻转）可主动更新并播报；静默变化不打断用户当前任务。
- 刷新与筛选、分页、选择协同：保留用户上下文，新增与移除数据的位置可预期。

### 27.31 断线与重连

- 断线后界面立即显示连接状态（顶部状态条或状态点），不伪装成功，也不清空已加载数据。
- 自动重连采用退避策略并限制次数，重连过程可见，支持用户手动重试。
- 重连成功后重新校验关键数据（列表、详情、权限），不需要整页刷新但必须修正过期状态。
- 指令发送状态不明时显示“发送中 / 结果未知”，确认结果前禁止重复提交，不自动重发。
- 提交类操作使用唯一请求标识，恢复后按标识去重，避免重复创建工单、订单等副作用数据。
- 离线期间的输入保留在本地，恢复后按保存与冲突规则处理，不丢失用户修改。

### 27.33 路由与深链接

- URL 记录对象 ID、Tab、筛选条件与关键视图参数，刷新、复制链接与新标签页打开都能恢复当前上下文。
- 参数过多或含敏感条件时使用短链或视图 ID，不在链接中泄露无关信息。
- 对象不存在或已删除时显示“未找到”，并提供返回列表、创建入口或建议链接。
- 无权限时明确区分“登录”“申请权限”“切换账号”等有效路径，不只显示空白或错误页。
- 非法或过期参数降级到安全的默认视图；单页应用路由变化后更新页面标题与焦点。
- 深链接在跨设备打开时按当前权限与数据状态正确降级，不暴露越权数据。

### 27.35 Command / 快捷操作

- Command Palette 提供统一入口：命令、全局搜索、最近访问与快速跳转合并为一个可搜索列表。
- 声明搜索范围：命令、页面、对象、文档与设置；范围过大时分段显示并标明来源。
- 键盘上下方向键选择，Enter 执行，Esc 关闭；选择状态持续可见并播报。
- 结果按权限过滤：无权限的命令不出现或显示不可用原因，不以搜索暴露敏感对象。
- 最近访问只记录当前用户有权限查看的对象，支持清除历史。
- 打开与关闭后焦点返回原位置；触屏上通过全局搜索按钮提供等价入口。

### 27.36 操作打断

- 请求进行中切换页面不取消必要的写操作，返回后以结果状态补报；读请求可安全取消。
- Modal 被意外关闭（遮罩、Esc、外部事件）时保留已完成步骤的草稿，并提示恢复入口。
- 长任务运行时退出页面提供“后台继续 / 等待完成 / 取消”的明确选择，结果以通知补报。
- 上传中关闭页面或断线时记录进度与已上传分片，恢复后可续传或重新上传，不静默丢弃。
- 编辑过程中权限变化、对象被删除或设备离线时保留本地修改并提供安全出口（另存、复制、导出）。
- 打断恢复后重新校验上下文，不基于过期数据继续操作。

### 27.37 Session / 超时

- 登录过期或 Token 失效时明确提示并停止提交；刷新页面或重新登录后回到原上下文。
- 操作过程中 Token 失效不静默重发：先刷新凭证或引导重新登录，恢复后继续原操作或提示重试。
- 重新登录后恢复原页面、路由与可恢复的本地状态；不自动执行敏感操作。
- 未保存内容在超时前与超时后都保留在本地，重新登录后提示恢复或放弃。
- 长任务不因 Session 过期而中断：任务在服务端继续，界面以只读 + 重新登录入口呈现。
- 安全超时前警告并允许续期；超时后的离开保护、自动保存与恢复路径统一。

### 27.38 乐观更新 Optimistic UI

- 仅对可预期结果、可逆且失败成本低的操作使用乐观更新：切换开关、状态标记、排序、轻量字段修改。
- 乐观更新期间显示处理中状态（如“保存中”），完成后确认；不伪装为已完成。
- 失败时回滚到服务端真实状态并提示原因；回滚不覆盖用户后续新修改。
- 连续修改合并为一次提交，以最后写入为准，避免并发乱序覆盖。
- 高风险操作禁止乐观更新：删除、发布、权限、金额、批量破坏性操作必须等待服务端确认。
- 乐观更新的最终状态以服务端为准，界面始终展示可解释的当前状态。

### 27.39 批处理执行反馈

- 批量操作实时显示进度与数量；部分失败时汇总“成功数 / 失败数”，失败项逐条列出原因。
- 失败项支持只重试失败项，重试前可修正参数；不得要求重跑全部成功项。
- 支持导出失败列表（CSV 等）与复制失败原因。
- 用户可取消剩余任务，已执行项结果保留并汇总；取消动作本身有确认与反馈。
- 批量操作完成与失败通过通知或任务中心补报，不阻塞当前页面。
- 成功 / 失败统计口径一致（含跳过、重复、无变化项），不把跳过伪装为成功。

### 27.40 任务队列

- 任务状态统一为 Waiting / Running / Paused / Completed / Failed / Cancelled，各状态有明确可执行动作。
- 并发数量可配置并有默认上限；超过上限的任务进入 Waiting 并显示排队位置。
- 支持优先级排序与手动调整；调整不打断 Running 中的任务。
- 暂停 / 继续作用于可暂停任务；不可暂停的任务不提供虚假按钮。
- 任务支持后台运行：离开页面不中断，完成后通过通知补报并可跳转查看。
- 失败任务提供重试、查看日志与移除；队列持久化规则与清理策略明确。

### 27.41 进度与取消

- 进度分确定与不确定两类：可计算百分比时显示百分比，不可计算时使用不确定指示，不伪装百分比。
- 多阶段任务显示当前阶段与阶段进度；预计剩余时间仅在估算可靠时展示。
- 取消按钮在任务可取消期间始终可用；不可取消的任务不显示取消按钮并说明原因。
- 取消后说明已完成数据的处理方式（保留、回滚或清理），部分完成结果明确可见。
- 进度更新不打断用户当前操作；完成、失败与取消通过可访问方式播报。
- 取消与确认的语义不混用：取消只停止未执行部分，不回滚已完成结果（需回滚的另设入口）。

### 27.42 页面刷新与数据恢复

- F5 / 刷新后恢复编辑状态：未保存内容存入本地草稿，重载后提示恢复。
- 明确临时数据存放位置与有效期：本地草稿、会话存储或服务端草稿，过期自动清理并提示。
- 恢复草稿前展示修改时间与内容摘要，由用户选择恢复或放弃。
- 恢复失败（格式损坏、版本过旧）时保留原文并提供导出，不静默丢弃。
- 用户主动放弃草稿需确认；放弃后彻底清理，不再提示恢复。
- 刷新后重新校验权限与数据版本，恢复内容不得基于过期数据。

### 27.43 帮助与解释交互

- Tooltip 用于短解释（图标、缩写）；Help Text 用于字段规则；Info Popover 用于较长背景；首次引导用于流程教学，各司其职。
- 帮助内容不阻碍操作：不拦截焦点、不覆盖控件、可随时关闭；关键信息不只在 Hover 中。
- 支持“不再提示”，但核心帮助入口保持可再次访问；用户可重新开启引导。
- 帮助文案说明“是什么、为什么、怎么做”，不只重复字段名。
- 错误与风险提示优先使用可见的字段级信息，不用 Tooltip 承载必须看到的内容。
- 引导完成进度可跳过、可中途退出，退出后保留用户已完成步骤。

### 27.44 系统级通知

- 页面内反馈用于即时结果，Toast 用于短时结果，Notification 用于需处理的事项，系统通知用于后台完成与离线提醒，层级清晰。
- 后台任务完成后发送通知，点击通知跳转到对应结果页并定位到任务。
- 通知支持关闭、标记已读与“不再提醒此类通知”的偏好设置。
- 通知内容包含对象、结果与时间，操作动词明确；失败通知附带重试或查看入口。
- 通知频率有限流：同类通知合并，不重复打扰。
- 系统通知被用户关闭时，站内通知中心仍保留完整记录。

### 27.45 可访问动态反馈

- Loading、保存成功、错误、新消息等动态变化使用 `aria-live` / `role=status` / `role=alert` 播报，读屏可感知。
- 用 polite 播报非紧急状态，assertive 只用于需要立即注意的错误；不播报每个键入字符。
- 动态更新的区域保持稳定 DOM，播报内容简明，包含结果与下一步。
- 进度、数量与状态变化播报合并为一次完整句子，避免碎片化重复。
- 视觉反馈与播报同步：颜色、图标变化的同时给出文本状态。
- 焦点不因动态更新被抢走；可选的新内容进入读屏顺序的自然位置。

### 27.46 输入法与组合输入

- 中文 IME 等组合输入期间不提前触发搜索、过滤或提交；以 `compositionstart` / `compositionend` 判定输入完成。
- Enter 在候选词选择状态下确认候选词，不误触发表单提交或搜索。
- 组合输入结束后再执行防抖查询；回退修改以最终确认的文本为准。
- 快捷键与 Enter 提交在组合输入期间被屏蔽，输入法需要的按键完整保留给 IME。
- 粘贴、自动补全等非组合输入路径同样校验最终文本，不做中间态提交。
- 多语言输入法（中文、日文、韩文等）行为一致；测试覆盖组合输入与候选词场景。

### 27.47 数据刷新与用户编辑冲突

- 用户正在编辑字段时，后台数据更新不得直接覆盖正在编辑的值；编辑完成后按冲突规则合并或提示。
- 列表排序或数据变化时，不移动用户当前正在操作的行的位置，或明确高亮并保留焦点。
- 正在编辑、正在查看详情或正在执行批量操作时，可冻结实时刷新并提示“有新数据”。
- 数据变化后提供明确的“应用更新”入口，由用户决定何时刷新视图。
- 后台更新与本地修改冲突时按最后写入 / 字段级合并处理，任一方修改不丢失。
- 刷新后焦点、选择与滚动位置尽量保留，被删除对象降级为明确的状态提示。

### 27.48 恢复与逃生路径

- Error、无权限、对象已删除、页面失效等状态必须提供明确返回位置：返回列表、回到首页或安全默认视图。
- 编辑器异常时保留返回、保存副本、导出内容等安全出口，不把用户困在错误页。
- 每个错误状态说明原因与可执行的下一步，不只显示错误码或空白页。
- 逃生路径始终可见：面包屑、返回按钮与全局导航至少一种可用。
- 未保存内容在异常状态下可保存副本或导出，避免用户数据丢失。
- 恢复后可回到出错前的位置或继续原任务；无法恢复时明确告知。

### 27.49 无障碍交互

- 优先使用原生语义元素；自定义组件必须实现对应角色、名称、值、状态、键盘行为和焦点管理。
- 所有功能可用键盘完成，焦点始终可见且不被遮挡；页面提供跳过重复导航到主内容的方式。
- 文本与背景、控件边界、焦点标识满足 WCAG 2.2 AA 对比度要求；状态、错误和图表不仅依赖颜色。
- 界面在 200% 文本缩放和 400% 页面缩放下不丢失核心内容或操作，不因固定高度截断错误和说明。
- 动态结果、保存状态和短反馈使用适当的 `aria-live`；阻塞性错误使用 alert 语义，但避免频繁播报每个键入字符。
- 图像、图表、3D 和状态图标提供与任务相关的文本替代；装饰图标从辅助技术隐藏，纯图标按钮提供 `aria-label`。
- 时限、闪烁、自动更新和动效必须可暂停、延长或减弱；安全超时在结束前警告并允许续期。
- 核心流程使用键盘、常用读屏、高对比模式、减弱动效和触屏实机完成验收，不仅依赖静态扫描。
